# Berth Desk — 접안 계획 · 체선료 프로토타입

울산 CLX 액체부두의 접안 계획 · 체선료 화면이다. 화면 틀은 SK Seagate 항무 웹사이트(사용자가 준 Berthing Schedule 캡처), 내용 화면은 실제 운영 중인 항만 사이트(부산항 신선대감만터미널 정보조회서비스의 본선작업현황 · 선석배정 현황, 울산항만공사 PortWise 선박 카드)의 문법을 따랐다. 어느 화면이 어느 사이트를 따랐는지는 [docs/design-references.md](docs/design-references.md)에 있다.

- 작성: 2026-11-12 · 상태: 프로토타입 (팀 검토 전)
- 데이터: 모두 목업이다. 선박 · 선명 · MMSI · 계약값은 가상이고, 부두 24곳 제원과 계산 규칙은 멘토링 자료와 팀 규칙 표(`ulsan-clx/ppt-v1`)를 따른다. 후보 금액은 팀 수리계획법(`docs/milp/ppt`)이 샘플 주간 54건으로 실제로 계산한 결과다.
- 날짜: 계획 시작이 늘 '내일 00:00'이 되도록 화면에서 날짜만 옮긴다. 주소 뒤에 `?now=2026-11-12T15:00`을 붙이면 기준 시각을 고정한다.

## 실행

```bash
python3 console/serve.py
```

<http://127.0.0.1:8777> 을 Chrome · Edge에서 연다 (`file://`로는 데이터를 못 읽는다). 빌드는 없다. 지도 타일은 인터넷이 필요하고, 못 받으면 해안선 바탕으로 바뀐다.

## portwise에서 뺀 것 · 넣은 것

- 뺀 것: 3D 뷰, 해운(운임지수 · 유가), 해무, 혼잡도 격자, 라이브맵 집계, 대기오염, 지도 레이어 패널(항로 · 보고선 · 도선 구역)
- 남긴 것: 2D 지도의 선박 · 부두 · 정박지, 선박을 누르면 열리는 카드(제원 · 항행 상태 · AIS 갱신 · 시설 사용), 선박 목록
- 넣은 것: ETA 변경 감지, 접안 계획 후보 비교, 계산 근거, 보고서, 승인, 계획 버전과 Berthing Schedule 반영, 변경 이력, 데이터 연계 상태

## 시연 순서 (5분)

1. 운영 현황 — 현황 요약(현행 계획 $479,697 · 위반 14건), 선석 작업현황판, ETA 변경 3척 알림.
2. AIS — 계류 중인 배(초록)를 눌러 시설 사용, 입항 예정 배(빨강)를 눌러 AIS ETA와 계획 ETA 차이를 본다.
3. Berth Optimization — 후보 비교 표에서 1안 $216,986 · 2안 동률 · 3안 부두 유지 $362,079를 견주고, 금액을 눌러 산출 근거를 연다. 보고서를 작성해 승인 요청한다.
4. 오른쪽 위 사용자를 승인권자 B로 바꾼다 → 승인 관리 → 검토 → 확인 사항 체크 · 결재 의견 → 승인.
5. Berthing Schedule — 적용 계획 v2, 바뀐 칸이 노란 테두리와 이전 값으로 보인다. ETB Change Log에 변경이 남는다.

위 링크줄의 '시연 초기화'를 누르면 처음 상태로 돌아간다. 주소에 `?review=1`을 붙이면 화면 요소마다 반영한 요구사항 번호가 겹쳐 보인다(검토용).

## 요구사항 반영

기준은 세 가지다: 요구사항서 실시간 탭의 비기능 NFR-01~22, WBS 시트 '숨은 요구 후보' 탭의 비기능 · UI/UX 후보(N · U, 이 저장소의 [15-hidden-requirements.md](../docs/requirements/15-hidden-requirements.md)), 그리고 이번 지시(3D 빼기 · 선박 클릭 정보 · 보고서 생성 · 확인 · 관리자 승인 · 승인하면 접안 스케줄 조회 · 캡처 화면 모양).

## 실제 솔루션으로 옮길 때

- `js/core/api.js`의 함수 몸통을 [docs/api.md](docs/api.md)의 엔드포인트 호출로 바꾼다. 화면 코드는 그대로 쓴다.
- 역할 · 버전 · 보고서 · 기록은 지금 브라우저 저장소에 있다 → Spring 업무 DB(`app` 스키마)로 옮기고 기록 표는 덧붙이기만 허용한다.
- 역할은 위 '사용자' 선택으로 흉내 냈다 → 로그인 계정에서 정한다.
- 후보 계산 버튼은 진행 단계만 보여 주고 미리 계산한 결과를 다시 불러온다 → `POST /api/v1/optimizations` + SSE로 바꾼다.
- 보고서 문장은 템플릿이다 → LLM 초안 + 숫자 대조(NFR-04)로 바꾼다.
