# 기존 데모와 Kubernetes 배치를 연결한 시연

기존 화면의 [S05 강풍 예보와 선박 집중 샘플](../data/scenarios/S05-storm-rush.json)을 화면과 배치에서 각각 실행한다. 화면에서는 접안 순서가 왜 바뀌었는지 보여 주고, Kubernetes에서는 같은 입력으로 검증된 보고서를 저장한다.

## 약 3분 시연 순서

1. [로컬 데모](http://127.0.0.1:18080/)를 열면 `S05-storm-rush`가 자동으로 계산된다. 강풍으로 새로 접안할 수 없는 시간대가 있고, 입항 예정 선박 9척의 접안 순서를 정해야 하는 가상 상황이다. [클러스터 기동 방법](../deploy/k8s/local/README.md)
2. **접안 계획 비교**에서 기준안과 1안을 바꿔 본다. 1안은 V05의 6번 부두 접안을 11월 12일 04:30에서 강풍 시작 전인 11월 11일 02:30으로 앞당긴다. V05를 누르면 계산서에서 계약 조항에 따른 허용 정박시간 12시간을 확인할 수 있다.
3. **리스크 · 민감도**에서 고정 선박 F1 일정이 강풍 구간에 걸리는 경고와 야간 작업 등 현장 안전 경고를 보여 준다. 그다음 **보고서 · 메일**에서 금액, 결과 지문, 미리보기 상단의 실행 ID를 확인한다.
4. 저장소 루트에서 아래 명령을 실행한다. 화면의 실행 ID를 넘기면 그 API 실행을 불러온다. 스크립트는 같은 샘플로 CronJob 템플릿에서 수동 Job을 만들고, 완료 후 볼륨에 있는 보고서를 읽어 대조한다.

```bash
python3 demo/scripts/compare_sample_batch.py --run-id 화면의_실행_ID
```

5. 출력된 `comparison.md`에서 입력, 엔진·규칙 버전, 후보 금액·접안 순서와 결과 지문이 일치하는지 보여 준다. 같은 폴더의 `batch-report.html`은 브라우저에서 열 수 있고, `batch-report.json`에는 배치의 계산 근거와 검사 결과가 들어 있다.

화면을 열기 전에 기본 S05를 준비하려면 `--run-id` 없이 실행한다. 다른 샘플은 화면에서 원본 시나리오를 실행해 그 ID를 넘기거나 `--scenario S14-contract-terms`처럼 선택한다. 스크립트는 원본 샘플과 입력이 일치하는지 검사하며, 선택한 시나리오를 이번 Job에만 전달한다. 이미 같은 날짜·버전·결과의 보고서가 있으면 배치 로그에 `already_exists`가 기록되고 기존 파일을 검증한다.

## 발표 결론

> 강풍과 선박 집중을 가정한 S05에서 1안은 V05를 강풍 전에 접안시켜, 도착 순서 기준안보다 예상 체선료가 2만 5,430.55달러, 약 22.5% 낮았습니다. 화면에서 선박별 계산과 계약 근거를 확인할 수 있고, Kubernetes 배치도 같은 접안 순서와 금액이 담긴 보고서를 저장했습니다. 담당자는 강풍 구간의 고정 일정과 야간 작업 경고를 검토한 뒤 접안안을 결정합니다.

이번 검증은 가상 샘플의 계산 결과를 비교했다. EKS에 연결하면 같은 시나리오로 수동 Job을 먼저 실행하고, 저장된 S3 보고서를 화면의 결과 지문과 대조한 뒤 예약을 활성화한다. [EKS 연결·배포 가이드](../deploy/README.md)
