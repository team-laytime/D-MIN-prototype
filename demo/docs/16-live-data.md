# 16 · 실시간 공공 데이터 연결 — 무엇이 되고, 무엇이 막혔나

작성 2026-11-12 · 선박 위치·ETA를 실제 공공 API로 받아 지도와 선박 카드에 띄우고, 같은 데이터로 예시 시나리오를 만들어 계산까지 돌린 결과다. 가상 시나리오(S01~S16)는 그대로 두었다.

## 한 줄 판단

실제 선박을 지도에 띄우고 ETA까지 보는 것은 **기술적으로 된다.** 현업이 쓸 가치가 있는지는 **아직 증명하지 못했다.** 막힌 곳은 기술이 아니라 데이터(계약 조건, 선박 제원, ETA 신뢰도)다.

## 연결한 API (전부 공공데이터포털, 키 하나로 호출)

| 용도 | API | 호출 | 우리 서버 경로 |

- 키는 서버만 가진다. 서버가 5분(입항 신고)·30초(위치) 캐시로 대신 부르고, 실패하면 마지막 성공값을 `stale`로 내려 준다. 키는 응답·로그·오류 문구에 넣지 않는다.

## 실행

```bash
cd demo
cp .env.example .env            # PUBLIC_DATA_SERVICE_KEY= 에 Decoding 키를 넣는다 (.env는 커밋되지 않는다)
make setup
set -a; . ./.env; set +a; make serve          # 서버 8000
cd .. && bun install && bun run dev           # 화면 5174, /api는 8000으로 프록시. 지도의 '실시간 AIS 보기' 버튼
PYTHONPATH=demo/src demo/.venv/bin/python demo/scripts/live_scenario.py   # 실시간 예시 시나리오 + 계산
```

GitHub Pages(정적 사이트)에는 서버가 없어서 실시간 버튼이 나타나지 않는다. 가상 시나리오는 그대로 동작한다.

## 실시간 예시 시나리오 (`scripts/live_scenario.py`)

SK 시설(SK부이·SK2/4/5부두)로 신고된 입항 건을 받아 시나리오를 만들고 `demurrage run`과 같은 파이프라인을 돌린다. 이미 부이에 댄 배는 운항정보의 실제 접안 시각으로 `WORKING` 처리한다. 값마다 실제/가정을 `provenance`로 남긴다.

- **실제**: 선명, ETA, 총톤수, 선종, 화물량, 예정 시설, 전출항지, 실제 접안 시각, 항내 흘수
- **가정**: DWT(총톤수×1.7~1.87), LOA, 병행부 길이, 자재코드, **계약 조건(Laytime·체선료 단가)**, 하역 능력, 조석 시간창, 항외 선박 흘수
- 2026-11-12 18:19 기준 5척. 결과는 기준안·후보 모두 $0, 개선 없음(선박이 같은 부두를 두고 겹치지 않음). **금액은 가정이라 업무 결론이 아니다.** 확인한 것은 "실제 입력으로 계산이 끝까지 간다"는 점이다.

## 실시간으로 들어온다는 것을 확인하는 법

서버(`make serve`)를 띄운 뒤 아래 한 줄을 돌리면 7개 항목을 검사하고 판정(통과/실패)을 출력한다. 선박이 움직이는 것을 눈으로 보여 줄 때도 이 순서로 한다.

```bash
cd demo
set -a; . ./.env; set +a                          # 키를 이 터미널에만 올린다 (4번 검사에 필요, 없으면 4번만 생략)
PYTHONPATH=src .venv/bin/python scripts/verify_live.py
```

| 검사 | 증명하는 것 | 실패하면 |
|---|---|---|
| 1 서버·선박 목록 | 서버가 살아 있고 울산항 선박을 돌려줌 | 서버 미기동 또는 키 누락(503) |
| 2 최신성 | 가장 최근 수신이 몇 분 전인가 | 원본 갱신 중단 |
| 3 값이 바뀜 | 갱신이 일어나면 위치·수신 시각이 바뀜(고정 샘플이 아님). **원본이 약 5분 주기 일괄 갱신이라 최대 6분 기다린다** | 서버 캐시 문제 또는 원본 중단 |
| 4 서버 값 = 원본 값 | 같은 선박을 공공데이터포털에서 직접 받아 위도·경도가 일치 | 서버가 값을 가공·캐시하며 어긋남 |
| 5 입항 예정(ETA) | 현재 이후 입항 예정이 들어옴 | 입항 신고 API 미승인·한도 |
| 6 키 유출 없음 | 응답에 서비스키가 없음 | 즉시 중단, 키 재발급 |

그다음 **사람이 눈으로 대조**한다(스크립트가 선박 3척의 링크를 출력한다).

1. 스크립트가 알려 준 선박의 MMSI로 VesselFinder 또는 MarineTraffic에서 위치를 연다.
2. 우리 지도(`http://localhost:5174` → '실시간 AIS 보기')에서 같은 선박을 눌러 위치·속력이 같은 해역·비슷한 값인지 본다. 외부 사이트는 갱신 시점이 달라 수백 m~수 km 차이가 날 수 있다. 같은 해역·같은 방향·비슷한 속력이면 맞다.
3. 선박 카드의 '마지막 수신' 시각이 지금보다 몇 분 전인지 본다. 5분쯤 뒤 화면이 갱신되면 값이 바뀐다.

**팀원에게 확인시키는 방법**
- 가장 확실한 것: 팀원이 자기 PC에서 위 절차를 그대로 돌린다. **키는 팀원이 data.go.kr에서 직접 신청해 자기 `demo/.env`에 넣는다**(키를 주고받지 않는다. 승인은 대부분 자동이고, 같은 API 3개를 신청한다).
- 키 없이 보여 줄 때: 화면 공유로 검증 스크립트 출력과 지도를 같이 보여 준다. 출력 전체(통과/실패 줄 포함)와 지도 화면을 같은 시각으로 캡처해 남긴다.
- 스크립트 출력에는 서버 수신 시각이 들어 있어 "지금 받은 값"이라는 증거가 된다. 결과를 PR이나 문서에 붙일 때는 키가 없는 출력만 붙인다(스크립트는 키를 출력하지 않는다).

## 키 관리 원칙

- 실제 키는 `demo/.env`(커밋 금지, `.gitignore`)에만 둔다. 저장소에는 값이 빈 `demo/.env.example`만 올린다.
- 브라우저 코드(`src/`)에는 키를 넣지 않는다. 정적 사이트에 들어간 값은 모두에게 공개된다.
- 채팅·이슈·PR·로그에 붙여 넣지 않는다. 노출됐다면 포털에서 키를 재발급한다.
