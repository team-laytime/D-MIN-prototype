## 2. 변수

| 종류 | 기호 | 한글 이름 | 뜻 · 왜 필요한가 | 쓰이는 식 |
|---|---|---|---|---|
| 결정 | u[i,b,k] | 시간창선택 (0/1) | 배 i를 부두 b의 k번째 시간창에 댄다. 부두 배정과 "언제쯤"을 한 번에 정하고 접안 금지 규칙을 식 없이 지키게 한다 | (1)(2)(5)(7) |
| 결정 | y[i,j] | 앞뒤순서 (0/1) | i가 j보다 먼저. PoC가 묻는 접안 순서 | (3)(4), 후보 |
| 결정 | t[i] | 접안시각 (ETB) | 예상시작·작업완료·호스분리·이안이 모두 여기서 나온다 | (2)~(6) |
| 따라 나옴 | P[i] | 정박개시 | 허용시간이 돌기 시작하는 시각. PPT 09·10쪽 갈래 | (5)(6) |
| 따라 나옴 | D[i] | 체선시간 | Demurrage Time. 목적함수의 유일한 변수 | 목적, (5) |
| 따라 나옴 | O[i,w], b[i,w] | 기상체선시간, 스위치 | 기상 악화 제약 시간 w 중 이 선박의 사용시간에 든 시간 | (5)(6) |

파라미터: 허용시간 L[i](LayTime), 요율 r[i], 공제비율 ρ[i](1/2), Switching s[b], 호스분리까지 q[i,b] = 1h + 작업시간 + 호스분리 소요, 이안까지 g[i,b] = 1h + 작업시간 + 2h, 배타구간 e[i,b] = g − 2h, 시간창 [α, β], 고정개시 c, 기상 악화 제약 시간, 큰수 M. 선석배정 x[i,b] = Σ_k u[i,b,k].

시간창 예 (S05의 V04, 석유제품선·GRT 42,000톤을 #7에): 도착 + Direction 전(11/10 10:30 전), 새벽 02~08시, FIX 선박 F1 앞뒤(11/10 21:04 ~ 11/12 07:30), 기상 악화(11/11 09:00 ~ 11/12 04:30)를 빼면 시간창 1) 11/10 10:30~14:59 2) 15:00~21:03 3) 11/12 08:00~ 이 남는다. 1과 2는 정박개시 규칙(ETANR 09:00 + 6h = 15:00)에서 나뉜다: 15:00 전에 대면 정박개시 = 접안시각(접안형), 뒤에 대면 15:00(고정형).

## 3. 식

```
목적  min Σ_i ( r[i] ÷ 24 ) × D[i]
      최소화: 선박마다 ( 요율 ÷ 24 ) × 체선시간 을 더한 값

(1)   Σ_b Σ_k u[i,b,k] = 1
      그 배의 시간창선택을 모두 더하면 1

(2)   Σ α[i,b,k] × u[i,b,k] ≤ t[i] ≤ Σ β[i,b,k] × u[i,b,k]
      고른 창의 창시작 ≤ 접안시각 ≤ 고른 창의 창끝

(3)   t[j] ≥ t[i] + g[i,b] + s[b] − M × ( 3 − y[i,j] − x[i,b] − x[j,b] )
      t[i] ≥ t[j] + g[j,b] + s[b] − M × ( 2 + y[i,j] − x[i,b] − x[j,b] )
      뒤 배 접안시각 ≥ 앞 배 접안시각 + 앞 배 이안까지 + Switching        (둘 다 부두 b일 때)

(4)   t[j] ≥ t[i] + e[i,b] − M × ( 3 − y[i,j] − x[i,b] − x[j,b′] )
      t[i] ≥ t[j] + e[j,b′] − M × ( 2 + y[i,j] − x[i,b] − x[j,b′] )
      뒤 배 접안시각 ≥ 앞 배 접안시각 + 앞 배 배타구간                      (동시 작업 금지 짝일 때)

(5)   P[i] ≤ Σ_접안형 β[i,b,k] × u[i,b,k] + Σ_고정형 c[i,b,k] × u[i,b,k]
      P[i] ≤ t[i] + Σ_고정형 max( 0, c[i,b,k] − α[i,b,k] ) × u[i,b,k]
      접안형 창이면 정박개시 ≤ 접안시각, 고정형 창이면 정박개시 ≤ 고정개시
      D[i] ≥ t[i] + Σ_b q[i,b] × x[i,b] − P[i] − L[i] − ρ[i] × Σ_w O[i,w] ,   D[i] ≥ 0
      체선시간 ≥ 호스분리( 접안시각 + 호스분리까지 ) − 정박개시 − 허용시간 − 공제비율 × 기상체선시간

(6)   O[i,w] ≤ ( 기상끝[w] − 기상시작[w] ) × b[i,w]
      O[i,w] ≤ 호스분리[i] − 기상시작[w] + M × ( 1 − b[i,w] )
      O[i,w] ≤ 기상끝[w] − P[i] + M × ( 1 − b[i,w] )
      O[i,w] ≤ 호스분리[i] − P[i] + M × ( 1 − b[i,w] )
      기상체선시간 ≤ 기상 악화 제약 시간 중 정박개시부터 호스분리 사이에 든 시간

(7)   최소 ≤ 기초재고 + 일별증감 누계 + Σ_i ( ± 물량[i] ) × Σ_(d일까지의 창) u[i,b,k] ≤ 용량
      날마다: 최소 재고 ≤ 그날까지 작업을 시작한 배의 물량을 더하고 뺀 재고 ≤ 탱크 용량

후보  Σ_i x[i, 방금 그 부두] + Σ_(이웃한 앞뒤) y[앞, 뒤] ≤ ( 항의 개수 ) − 1
      방금 찾은 배정과 순서 중 적어도 한 군데는 달라야 한다 → 다시 풀면 2안, 3안
```

- 큰 수 M: `− M × ( … )`의 괄호가 0이면 식이 켜지고 1 이상이면 꺼진다.
- (5): P는 클수록 체선이 줄어서 상한 두 줄만 있으면 PPT의 갈래대로 정해진다. D는 `D ≥ 식`, `D ≥ 0` 두 줄이 "둘 중 큰 쪽"이 된다.
- (6): 기상체선 시간을 세는 구간은 스크립트의 `--weather-from`으로 바꾼다(start = 정박개시~호스분리, end = 정박종료~호스분리, wait = 정박개시~접안). 5-1절 참고.
- 갈 수 없는 부두(제원·제품 그룹, Draft는 수입만)는 변수를 만들지 않는다. FIX·작업 중 선박은 시간창과 재고의 상수로 들어간다.

숫자 대입(GC-01, 변수 11개·제약 14줄)은 `python3 scripts/milp_berth_plan.py --walk GC-01`이 파라미터 → 변수 값 → 제약식 순서로 찍는다: Y 먼저(y = 0)면 t[Y] = 7, t[X] = 7 + 11 + 1 = 19, D[X] = 19 + 16 − 8 − 24 = 3 → 6,000. X 먼저(y = 1)면 t[Y] = 7 + 17 + 1 = 25, D[Y] = 25 + 10 − 10 − 12 = 13 → 52,000.

## 5. PPT를 식으로 옮기며 보인 것

### 5-1. 기상체선 시간은 해석에 따라 금액과 일정이 달라진다 [확인 필요]

PPT 11쪽은 "Demurrage Time −= 기상체선 시간 / 2"까지만 적었고, 멘토 설명은 "기상 악화 제약 시간이 이 선박의 시간 안에 들어 있으면 반씩 부담"이었다.

| 기상체선 시간으로 세는 구간 | S05 1안 | S14 1안: 엔진 탐색 → 수리계획법 | 무작위 300 중 일부러 늦춰 대는 해 |
|---|---|---|---|
| 정박개시 ~ 호스분리 (사용시간, 기본) | $47,919.45 | $20,791.66 → $17,041.66 | 18 |
| 정박종료 ~ 호스분리 (체선 기간) | $75,502.78 | $26,750.00 → $25,500.00 | 12 |
| 정박개시 ~ 접안 (기상 때문에 기다린 시간) | $47,919.45 | $26,625.00, 같음 | 0 |

앞의 두 해석에서는 솔버가 배를 일부러 늦게 대서 사용시간이 기상 악화 시간과 더 겹치게 만든다(S14의 K3은 4시간 30분). 규칙을 글자 그대로 따르면 생기는 결과이고 현장이 원할 일정은 아니다.

### 5-2. 일부러 기다리는 일정 [확인 필요]

PPT 09쪽 흐름도에서 LayCan From 전에 도착한 배는 From 전에 대면 정박개시 = ETB(Early Loading), From 이후에 대면 From의 06시(Daylight 선박 07시)다. 작업이 허용시간보다 긴 배는 From까지 기다렸다 대는 쪽이 낮다. 예: 11/10 18:00 도착·LayCan From 11/11·허용 12h·호스분리까지 16h·하루 $24,000 → 가장 이른 19:30에 대면 $4,000, 11/11 00:00까지 기다리면 $0. 엔진은 가장 이른 시각으로만 붙여서 이 선택을 보지 못한다. 무작위 300사례 중 23사례, 프로젝트 시나리오에서는 0.

### 5-3. 데모 엔진이 PPT와 다른 곳

| 항목 | 멘토링 PPT | 데모 엔진(11-09) |
|---|---|---|
| 조기 도착 선박의 정박개시 | LayCan From의 06시, Daylight 적용 선박은 07시 (09·10쪽) | 모두 06시 |
| Daylight 경계 | 일출 < ETANR < 일몰일 때만 + 6h (10쪽) | 일출·일몰과 같은 시각도 + 6h |
| 기상체선 시간 | 정의 없음 (11쪽) | "기상이 없었다면 댔을 시각 ~ 실제 접안" 중 체선 기간 |
| 조석 | 고려하지 않음 (12쪽) | 흘수 20 m 이상은 조석 시간창 |
| LayTime 절반 조건 | 흐름도 글자는 "원유 && CFR False" (10쪽) | CFR Plus 계약의 원유선 [확인 필요] |

### 5-4. 솔버의 "최적"도 검산이 필요하다

무작위 시험에서 HiGHS(scipy 1.18.1의 1.12.0)가 더 좋은 답이 있는데도 "최적"이라고 돌려준 풀이가 있었다. 사전처리(presolve)를 끈 풀이가 1,800번 중 3번, 큰 수 M을 빠듯하게 잡고 분 단위로 넣었을 때는 켠 풀이도 2번. 그래서 `milp_core.py`는 시간 단위로 넣고, M에 하루 여유를 주고, 매번 두 설정으로 풀어 더 좋은 쪽을 쓰며(엇갈린 횟수를 센다), 답은 늘 엔진 계산식과 검증기로 다시 확인한다.

## 6. 샘플 데이터가 들어가는 곳

멘토의 샘플 데이터: 부두 24곳 제원, 부두별 접안 가능 제품 그룹 33개, DWT 구간별 선박 제원·평균 체선료, 접안 계획 예시. 선석배정 변수는 "제품을 받는 부두 중 제원까지 맞는 부두"에만 만든다.

| 가상 선박 (샘플의 DWT 구간 평균) | 제품 그룹 | 제품을 받는 부두 | 제원까지 맞는 부두 |
|---|---|---|---|
| 소형 화학제품선, DWT 5천, 수입 | BENZENE | 3곳 | 4-1 |
| 중형 석유제품선, DWT 4.5만, 수출 | R-G | 9곳 | 6, 7 |
| 중형 석유제품선, DWT 4.5만, 수출 | DSL | 14곳 | 6, 7, 8 |
| 대형 원유선, DWT 10.5만, 수입 | CRUDE | 5곳 | 8, BUOY2, BUOY3 |
| 초대형 원유선, DWT 29.5만, 수입 | CRUDE | 5곳 | BUOY3 |

이 문서의 검증 숫자는 데모의 가상 부두 9곳으로 낸 값이다. 부두 제원·제품 표를 샘플 데이터 24곳으로 바꾸는 일이 남아 있다.
