# 12. 화면 설계 — SEAGATE 체선 관리 개선 컨셉

- 작성 2026-11-09 · 코드 `src/demurrage/web/`(index.html · styles.css · app.js, 프레임워크 없음)
- 화면 이름은 독자적으로 **Demurrage Planner**로 붙였습니다. SEAGATE·SK에너지의 로고·화면을 흉내 내지 않았고, 모든 데이터에 '가상 데이터' 표시가 붙어 있습니다.

---

## 1. 컨셉 — 무엇을 개선하나

우리 진단([`../../docs/seagate-diagnosis.md`](../../docs/seagate-diagnosis.md))으로는 SEAGATE(SK에너지 항무웹사이트)의 로그인 영역에 선석 예약·접안 계획·Berth Optimization·체선 리포트·Demurrage 요약이 이미 있습니다. 시스템은 **기록하고 계산**합니다. 그 사이의 판단, 곧 "이 순서로 붙이면 체선료가 얼마이고, 그 금액은 어느 계약 조항에서 나왔나"는 사람이 엑셀과 계약서를 오가며 합니다.

이 화면은 Ship Berthing 메뉴 옆에 붙는 확장 모듈을 가정합니다. 하는 일은 세 가지입니다.

1. **접안 계획을 체선료로 비교한다** — 도착 순서 기준안과 후보 3개를 같은 간트에 놓고, 무엇을 옮겨서 얼마가 줄었는지 보여 줍니다.
2. **금액마다 계약 조항을 붙인다** — 선박을 누르면 9단계 계산서가 열리고, 각 줄에 "계약서 CT-2611-05 Part I (H)" 같은 근거가 붙습니다. 누르면 계약서의 그 조항으로 갑니다.
3. **결정은 사람이 하고 기록은 남긴다** — 확정·취소·현업 반영은 담당자만 누르고, 기록은 덧붙이기만 됩니다.

v0.1 화면에 있던 질의응답 창("왜 1안이 싼가?")은 팀 결정으로 뺐습니다. 같은 질문에 대한 답은 계획 비교 화면의 '바뀐 것'과 '근거' 카드, 계산서가 직접 보여 줍니다.

## 2. 정보 구조

왼쪽 메뉴는 업무 순서대로 묶었습니다. 위쪽 막대에는 지금 보고 있는 시나리오가 늘 보이고, 눌러서 바꿀 수 있습니다.

- **선석 운영** — 접안 계획 비교 · 입항 예정 선박 · 부두·제약
- **체선료** — 선박별 계산서 · 리스크·민감도
- **계약** — 계약서(23건)
- **보고·결정** — 보고서·메일 · 확정·이력
- **시나리오** — 시나리오 라이브러리(16개)
- **관리** — 검증 · 아키텍처

처음 열면 대표 데모(S05)를 계산해 '접안 계획 비교'를 보여 줍니다.

## 3. 화면별

### 접안 계획 비교 (첫 화면)

위에서 아래로 "무슨 상황 → 얼마 → 어떻게 → 왜 → 누구"의 순서입니다.

1. **머리말** — 시나리오 이름과, 이 상황에서 판단할 점(카드의 질문)을 한 줄로.
2. **상황 카드** — 왼쪽은 상황과 판단할 점, 오른쪽은 '결과에서 확인할 것' 체크 목록, 관련 운영 기준(규칙 ID), 관련 계약 조항(누르면 계약서로).
3. **숫자 다섯 개** — 기준안 총액 · 선택한 안 총액(탐색 상태) · 절감액 · 하드 제약 위반 · 남은 리스크. 기준안이 성립하지 않으면(S15) '성립 안 함'과 이유, 절감액은 '비교 불가'로 바뀝니다.
4. **안 선택 + 부두별 간트** — 기준안/1안/2안/3안을 눌러 바꿉니다. 간트의 막대는 화물색(작업)과 옅은 색(접안 준비·이안), 아래 빨간 띠가 체선(정박종료 이후), 점선이 대기(ETA → 접안), 빗금이 강풍·정비 제한, 회색 배경이 야간, Buoy 아래 청록 띠가 조석 창입니다. FIX 선박은 자물쇠와 테두리, 작업 중 선박은 빗금 막대입니다.
5. **바뀐 것 / 이 안의 근거** — 기준안 대비 배정이 바뀐 선박을 증감 순으로, 각 줄에 계산서 요약 한 문장. 오른쪽은 탐색 결과(최적 증명, 확인한 상태 수), 규칙 상태(가정·미확정 포함 여부), 남은 리스크, 자체 검사 통과 항목.
6. **선박별 표** — 계약서, 부두, ETA, 접안, 대기, 정박종료, 호스 분리, 체선, 예상 체선료, 기준안 대비. 합계 줄이 총액과 같습니다.

### 계산서 서랍

간트 막대나 표의 줄을 누르면 오른쪽에서 열립니다.

- 맨 위: 금액(체선이 있으면 빨강, 없으면 초록)과 한 문장 요약 — "11/10 22:00 도착 → 선행 선박 대기 45.35h 기다려 #6 11/12 20:51 접안. 정박종료(11/12 16:00)보다 18.28h 늦게 호스 분리 → 체선 18.28h, $12,189."
- 계약 요약: 계약서 번호(링크)·상대방·허용 정박시간·체선료율·기상 공제·주간 NOR.
- 9단계: 도착·NOR → 접안 시각 → 작업 → 호스분리·이안 → 정박개시 → 허용 정박시간 → 정박종료 → 체선 시간 → 예상 체선료. 단계마다 값, 식에 숫자를 넣은 줄, 근거 칩. 접안이 밀렸으면 민 규칙과 구간이 목록으로 붙습니다.
- 근거 칩은 다섯 종류이고 색으로 구분합니다: 계약(파랑, 누르면 조항으로) · 운영 기준(회색, 규칙 ID) · 부두 기준(청록, Shifting 표) · 입력(흰색) · 실적(보라, 과거 작업 Rate).
- 맨 아래: 기준안과 이 안의 부두·접안·호스 분리·체선·금액 비교.

### 계약서

목록은 종류별(용선계약/FOB/CFR/CFR Plus)로 거르고, 각 줄에 허용 정박시간·체선료율·기상 감면·주간 NOR·쓰는 시나리오를 보여 줍니다. 상세는 종이 문서처럼 보입니다 — 당사자 칸, Part I 상자(계산에 쓰는 칸에는 '계산에 사용' 표시), 조항(각 조항에 연결된 규칙 ID), 리캡 전문. 계산서에서 넘어오면 해당 조항이 노란색으로 표시되고 그 위치로 스크롤합니다. 오른쪽에는 계산에 쓰는 조건, 규칙 ↔ 조항 대응표, 이 계약서를 쓰는 시나리오가 있습니다.

### 그 밖의 화면

- **입항 예정 선박** — 선박 제원·상태·계약서. ETA를 고쳐 '변경 내용으로 다시 계산'하면 원본은 그대로 두고 수정본으로 계산합니다(위쪽에 '수정본' 표시).
- **부두·제약** — 부두 제원과 Shifting 시간, 부두 사용 제한, 예보 구간별 접안 가능 여부, 야간·조석·동시 접안 규칙, 재고, 선박 × 부두 적합성 표(안 되는 이유를 칸에).
- **선박별 계산서** — 왼쪽 선박 목록(금액 순), 오른쪽 계산서 전체.
- **리스크·민감도** — 후보별 리스크 5종 카드(해당이 먼저), ETA ±6시간·예보 변경 때 총액과 순위 변화, 현업 확인이 필요한 가정 목록.
- **보고서·메일** — 보고서 미리보기, 숫자 대조 결과(금액·시각 422개), 내려받기(.docx·.md·.csv·메일), 메일 초안(복사만, 발송 기능 없음).
- **확정·이력** — 후보 상태(추천/선택됨/현업 반영 완료), 결정 기록, 감사 기록, 처리 단계 7개의 소요 시간, 재현 정보(시나리오·규칙 해시, 결과 지문). 확정 창에서는 담당자 이름이 필수이고, 남은 리스크가 있으면 확인 체크를 해야 확정됩니다.
- **시나리오 라이브러리** — 16개 카드를 분류별로. 카드마다 상황·판단할 점·확인할 것, 계산한 적이 있으면 기준안 → 1안.
- **검증** — 정답 세트 272칸 일치율, 검증 시나리오의 완전 탐색 비교, 지금 실행의 자체 검사.
- **아키텍처** — 프로젝트·백엔드 다이어그램.

## 4. 디자인 원칙

1. **숫자가 먼저, 근거는 한 번 눌러서.** 첫 화면에서 금액과 무엇이 바뀌었는지가 먼저 보이고, 왜 그런지는 선박을 누르면 나옵니다.
2. **색은 의미에만.** 막대 색은 화물 그룹, 빨강은 체선 금액, 호박색은 제한·주의, 초록은 줄어든 금액과 통과. 장식용 색은 쓰지 않습니다.
3. **업무 용어 그대로.** ETB, Laycan, NOR, Switching처럼 현업이 쓰는 말은 번역하지 않고, 설명이 필요한 곳에만 풀어 씁니다.
4. **도구 말투를 빼고 업무 말투로.** 화면에 'Agent', 이모지, "AI가 추천합니다" 같은 문구가 없습니다. 처리 단계는 '입력 검증 · 제약 정리 · 후보 탐색 · 체선료 계산 · 리스크 점검 · 보고서 작성 · 결과 검증'으로 부릅니다.
5. **정직한 진행 표시.** 계산 중에는 실제 경과 시간만 보여 줍니다. 진행률을 지어내지 않습니다.
6. **가상 데이터 표시는 늘.** 위쪽 막대와 계약서마다 '가상' 표시가 있습니다.

## 6. 구현 메모

- **프레임워크 없이 한 파일(app.js).** 빌드 도구가 없어 FastAPI가 정적 파일로 바로 냅니다. 화면이 11개로 늘었지만 상태가 '지금 시나리오·지금 실행·선택한 안' 셋뿐이라 아직 프레임워크가 필요하지 않습니다(ADR-008, ADR-013).
- **간트는 화면에서 그립니다.** 서버도 같은 내용의 SVG를 만들지만(보고서·문서용), 화면에서는 마우스를 올리면 세부 시각이 뜨고 누르면 계산서가 열려야 해서 HTML 요소로 다시 그립니다. 시각·금액은 서버 값을 그대로 쓰고, 화면은 위치만 계산합니다.
- **해시 주소.** `#/plan`, `#/contracts/CT-2611-05?c=Part I (H)`처럼 화면마다 주소가 있어 링크로 공유할 수 있습니다.
- **키보드.** Esc로 서랍·창을 닫습니다.
- **좁은 화면.** 900px 아래에서는 사이드바를 숨기고 카드를 한 줄로 쌓습니다(현장 태블릿 확인용 수준).
