
## 4. 명령줄로 같은 흐름 (화면 없이)

```bash
cd demo && PYTHONPATH=src .venv/bin/python -m demurrage run S05-storm-rush --out out --db sqlite:///runtime/demurrage.db --confirm 1안 --actor "선박 스케줄러" --reason "긴급 출하 V05 우선"
```

출력(요지):

```text
■ 시나리오 S05-storm-rush — 강풍 예보 + 선박 집중 (대표 데모)
  1. 입력검증 Agent … 7. 검증 Agent {"passed": 10, "total": 10}
  기준안(FCFS) $112,919
  1안 $87,489  절감 $25,431 (22.5%)  위반 0  최적 증명
  2안 $91,235  절감 $21,684 (19.2%)  위반 0
  3안 $92,300  절감 $20,619 (18.3%)  위반 0
  ✔ 담당자 선박 스케줄러가 1안 확정 기록
  산출물: out/<run_id>/ (report.md·html, mail.txt, timeline-*.svg, schedule-1안.csv, run.json)
```

규칙 표만 바꿔 다시 계산하는 시연: 접안 한계 풍속을 15 → 18 m/s로 바꾸면 17 m/s 예보가 더는 제한이 아니어서 결과가 바뀐다(기준안 $75,100 → 1안 $67,756, 규칙 버전 해시도 바뀜).

```text
POST /api/runs  {"scenario_id": "S05-storm-rush",
                 "rules_patch": {"terminal.weather_limits.berthing_wind_ms.PIER": 18,
                                 "terminal.weather_limits.berthing_wind_ms.BUOY": 18}}
```

기상 공제 비율(`contract.weather_deduction.ratio`)은 이제 계약서 값이 우선이라 S05에서는 바꿔도 금액이 그대로다. 계약서가 없는 입력에서 규칙 표 기본값이 쓰이는 모습은 정답 세트 GC-09가 보여 준다.
