# 원유 수입선 하역 일정 최적화 — 수리계획법 최종본

- 작성: 2026-11-11 · 기준: 팀 공유용 최종 정리 (본체 식 (1)~(8), 작업계획 생성 규칙 식 (9)~(20))
- 그림으로 된 것은 팀 피그마 파일 SKALA-P2-1의 '수리계획법' 페이지에 있다 — [수리계획법 최종본 묶음](https://www.figma.com/design/mDE8EoyYV0dS2WjtBLUoet/SKALA-P2-1?node-id=206-643) (2026-11-11에 넣음, 머리띠 1 + 판 9). 미리보기 그림은 `preview/`에 있다
- 이 파일과 피그마 보드는 `milp_final_content.py`(글) + `milp_final_example.py`(숫자)에서 `make_milp_board.py`로 만든다
- 표기: 대괄호 안이 아래첨자다. `z[i,k]`는 z에 아래첨자 ik

입항 건마다 미리 만들어 둔 작업계획 가운데 하나를 고른다. 부두가 겹치지 않고 원유 재고가 허용 범위를 벗어나지 않는 조합 가운데 총 예상 체선료가 가장 작은 것이 답이다.

## 1. 범위

- 대상은 원유 수입선이다. 원유탱크는 하나의 통합 저장공간으로 본다.
- 공정 원유 소비계획과 하역속도는 고정 입력값이다.
- 유형 1은 한 부두에서 전량 하역하는 작업계획만 만든다.
- 유형 2는 부두 이동과 분할 하역을 포함한 작업계획도 만든다. 유형 1의 계획을 모두 포함하므로 부두 이동은 선택 사항이다.
- 최적화 범위는 미리 만들어 둔 작업계획 집합이다. 만들지 않은 계획은 답이 될 수 없다.
- 야간 도선 제한은 접안할 수 있는지에만 적용한다. 야간이라는 이유만으로 하역을 막지 않는다.

## 2. 헷갈리기 쉬운 말

| 말 | 맞는 뜻 | 아닌 것 |
|---|---|---|
| 입항 건 i | 입항 한 번을 가리킨다. 같은 선박이 다시 오면 다른 i다. | 선박 이름이 아니다. |
| 작업계획 k | 입항 건 하나의 처음부터 끝까지의 일정이다. 부두 방문이 한 번일 수도, 여러 번일 수도 있다. | 대시보드의 후보안이 아니다. |
| 스케줄 후보안 | 모든 입항 건에서 작업계획을 하나씩 고른 조합이다. 대시보드의 1안 · 2안 · 3안이 이것이다. | 작업계획 하나가 아니다. |
| 야간 | 야간 도선 제한은 접안 시각에만 걸린다. 걸리는 접안은 직후 08:00로 미룬다 (FR-19). | 야간에 하역을 못 한다는 뜻이 아니다. 계약의 Daylight 조항(정박개시 계산, FR-32)과도 다른 것이다. |
| 최소 허용 재고 R_min | 재고가 이 값보다 내려가는 조합은 답이 될 수 없다. | 공정이 실제로 멈춘다는 뜻이 아니다. 재고가 0이라는 뜻도 아니다. |
| 사용시간 종료 H[i,k] | 계약이 사용시간의 끝으로 인정하는 호스분리 시각이다. 분할 하역이면 마지막 방문의 호스분리다. | 하역 완료 시각도, 이안 시각도 아니다. |
| 최적 | 만들어 둔 작업계획 안에서 총 예상 체선료가 가장 작은 조합이다. | 만들지 않은 접안 시각이나 물량 배분까지 따진 최적은 아니다. |
| 표기 | z[i,k]는 이 페이지의 다른 자료에서 z에 아래첨자 ik를 붙여 쓴 것과 같다. 그 자료들의 '후보'는 작업계획이고 '선박'은 입항 건이다. | 식이 다른 것이 아니다. 적는 방법만 다르다. |

## 4. 최적화 본체 — 식 (1)~(8)

### (1) 목적함수 — 총 예상 체선료 최소화

```text
min  ∑[i∈I] ∑[k∈Ω[i]]  C[i,k] · z[i,k]
```

- 한글 식: **모든 입항 건에 대해 (고른 작업계획의 체선료)를 더한 값을 가장 작게 만든다**
- 읽는 법: 고르지 않은 작업계획은 z = 0이라 곱하면 사라진다. C는 미리 계산해 둔 숫자다.
- 예제 · 식에 숫자를 넣으면: 총 체선료 = 0·z[A,1] + 5,000·z[A,2] + 37,000·z[A,3] + 0·z[B,1] + 2,250·z[B,2] + 15,750·z[B,3]
- 예제 · 1안 (A1 + B3): A1 $0 + B3 $15,750 = $15,750
- 예제 · 2안 (A2 + B3): A2 $5,000 + B3 $15,750 = $20,750

### (2) 입항 건마다 작업계획 하나

```text
∑[k∈Ω[i]]  z[i,k]  =  1        ∀ i ∈ I
```

- 한글 식: **한 입항 건의 선택 여부를 모두 더하면 정확히 1이다**
- 읽는 법: 두 개를 고를 수도, 하나도 안 고를 수도 없다. 입항 건마다 식이 한 줄씩 생긴다.
- 예제 · 입항 건 A (1안): z[A,1] + z[A,2] + z[A,3] = 1 + 0 + 0 = 1
- 예제 · 입항 건 B (1안): z[B,1] + z[B,2] + z[B,3] = 0 + 0 + 1 = 1

### (3) 충돌하는 작업계획은 같이 고르지 않는다

```text
z[i,k]  +  z[j,l]  ≤  1        ∀ ((i,k),(j,l)) ∈ F
```

- 한글 식: **충돌하는 두 작업계획의 선택 여부를 더하면 1 이하다**
- 읽는 법: 한쪽만 고르거나 둘 다 안 고른다. 충돌 쌍마다 식이 한 줄씩 생긴다.
- 예제 · 충돌 쌍 (A1, B1) · 1안: z[A,1] + z[B,1] = 1 + 0 = 1 ≤ 1 → 통과
- 예제 · 충돌 쌍 (A2, B2) · 1안: z[A,2] + z[B,2] = 0 + 0 = 0 ≤ 1 → 통과
- 예제 · 충돌 쌍 (A3, B3) · 1안: z[A,3] + z[B,3] = 0 + 1 = 1 ≤ 1 → 통과
- 예제 · A1과 B1을 같이 고르면: 1 + 1 = 2 > 1 → 답이 될 수 없다

### (4) 시간대별 원유 재고 수지

```text
R[t+1]  =  R[t]  +  ∑[i∈I] ∑[k∈Ω[i]]  q[i,k,t] · z[i,k]  −  D[t]        t = 0, …, T−1
```

- 한글 식: **다음 시점 재고 = 지금 재고 + (고른 작업계획이 이 구간에 넣는 원유) − (공정이 이 구간에 쓰는 원유)**
- 읽는 법: 구간마다 식이 한 줄씩 생긴다. q와 D는 미리 정해진 숫자다.
- 예제 · 1안 · 구간 t=1 (3.0h~9.0h): 다음 재고 R[2] = 지금 재고 8.5 + A1 하역 6.0 − 공정 소비 3.0 = 11.5
- 예제 · 1안 · 구간 t=7 (20.0h~22.0h): 다음 재고 R[8] = 지금 재고 12.0 + B3 하역 2.0 − 공정 소비 1.0 = 13.0
- 예제 · 나머지 구간: 구간 11개 전부는 판 8의 표에 있다 (단위: 만 배럴)

### (5) 처음 재고 고정

```text
R[0]  =  R⁰
```

- 한글 식: **계획 시작 시점의 재고는 주어진 처음 재고와 같다**
- 읽는 법: 계획 시작 전의 하역과 소비는 R⁰에 이미 들어 있다.
- 예제: R[0] = 10.0만 배럴 (계획 시작 시점의 재고)

### (6) 재고 부족 · 용량 초과 방지

```text
R_min  ≤  R[t]  ≤  R_max        t = 0, …, T
```

- 한글 식: **어느 평가 시점에도 재고는 최소 허용 재고 이상, 저장용량 이하다**
- 읽는 법: 평가 시점마다 식이 한 줄씩 생긴다. R⁰가 이미 범위 밖이면 어떤 조합도 답이 될 수 없으니 입력부터 확인한다.
- 예제 · 1안 (A1 + B3): 가장 낮을 때 8.5 (3.0h), 가장 높을 때 16.0 (28.0h) → 7.0 ≤ R[t] ≤ 18.0 통과
- 예제 · A1 + B2: 19.0h에 20.5 → 저장용량 18.0 초과 → 탈락
- 예제 · A3 + B1: 9.0h에 5.5 → 최소 허용 재고 7.0 미달 → 탈락

### (7) 변수 범위

```text
z[i,k]  ∈  {0, 1}
```

- 한글 식: **선택 여부는 0 아니면 1이다. 재고 R[t]는 연속 변수(실수)다**
- 읽는 법: 정수 조건이 붙은 변수는 z뿐이다. 그래서 혼합정수계획(MILP)이다.
- 예제 · 예제의 변수: z 6개 (A1, A2, A3, B1, B2, B3) + R 12개 (평가 시점 12개) = 18개
- 예제 · 예제의 제약식: 식 (2) 2줄 + 식 (3) 3줄 + 식 (4) 11줄 + 식 (5) 1줄 = 17줄. 식 (6)은 R의 상·하한

### (8) 작업계획이 지정된 FIX 입항 건

```text
z[i, k_fix[i]]  =  1        ∀ i ∈ I_fix
```

- 한글 식: **FIX 입항 건은 지정된 작업계획을 고른 것으로 고정한다**
- 읽는 법: 부두나 접안시각만 고정이면 식을 쓰지 않고, 그 조건에 맞는 작업계획만 Ω[i]에 남긴다. 하역 중인 입항 건은 지금 부두에서 남은 물량을 이어 하역하는 계획만 둔다 (FR-18).
- 예제: FIX 입항 건이 없다. 식 (8)은 쓰이지 않았다
- 예제 · 만약 B를 B1로 고정하면: z[B,1] = 1을 더한다. 남는 조합은 A1 + B1, A2 + B1, A3 + B1뿐인데 모두 탈락한다 (판 8의 1·3·7번). 가능한 조합이 없으므로 '실행 가능한 후보 없음'이다. 솔버도 같은 답을 냈다

### (+) 다음 스케줄 후보안을 낼 때만 더하는 식 — 덧붙임 · 정리본 식 (1)~(20) 밖

```text
∑[(i,k)∈S]  z[i,k]  ≤  |I| − 1
```

- 한글 식: **이미 낸 조합의 작업계획을 전부 다시 고를 수는 없다**
- 읽는 법: 입항 건 하나 이상은 다른 작업계획이 된다. 이 식을 더해 다시 풀면 2안, 한 번 더 하면 3안이다. 작업계획이 하나라도 다르면 다른 후보안으로 센다.
- FR-42 '후보끼리는 1척 이상 배정이 다르게 한다', 후보는 최대 3개

- 답이 없을 때: 식 (2)(3)(6)(8)을 모두 지키는 조합이 없으면 답이 없다. 재고 범위를 느슨하게 풀어 주지 않고 '실행 가능한 후보 없음'으로 알린다 (FR-43).
- 시간이 모자랄 때: 제한시간 안에 최적임을 증명하지 못하면 그때까지의 최선안과 최적성 갭을 함께 낸다 (NFR-09).
- 크기: 변수는 z가 작업계획 수만큼, R이 T + 1개다. 제약식은 입항 건 수 + 충돌 쌍 수 + T + 1개에 FIX 수가 더해지고, 재고 범위는 R의 상·하한으로 넣는다.

## 5. 작업계획 생성 규칙 — 식 (9)~(20)

### 유형별 물량

작업계획 하나가 부두를 몇 번 방문하고 물량을 어떻게 나누는지.

**(9) 유형 1 · 한 부두에서 전량**

```text
M[i,k] = 1
Q[i,k,1] = Q[i]
```

- 한글 식: **방문은 한 번이고, 그 방문에서 남은 물량을 전부 하역한다**
- 예제 · A1: 방문 1번. 그 방문에서 12.0만 배럴 전부

**(10) 유형 2 · 분할 하역 허용**

```text
1 ≤ M[i,k] ≤ M_max[i]
∑[m=1..M[i,k]]  Q[i,k,m]  =  Q[i]
Q[i,k,m] > 0
```

- 한글 식: **방문은 1번 이상 M_max번 이하이고, 방문별 하역량을 모두 더하면 남은 물량 전부다**
- 예제 · 설명용 A4: 방문 2번 = BUOY3 7.0만 + BUOY2 5.0만 = 12.0만 배럴

문장으로 정해 두는 것

- 유형 2에도 방문이 한 번인 계획을 넣는다. 그래서 유형 2의 답은 유형 1의 답보다 나빠지지 않는다.
- 방문별 하역량 Q[i,k,m]을 몇 배럴 단위로 나눠 만들지와 방문별 최소 하역량은 생성 설정이다.

### 방문 일정

방문 하나의 다섯 시각. 일정한 속도로 중단 없이 하역하는 경우다.

**(11) 첫 접안**

```text
s[i,k,1]  ≥  ETA[i]  +  Direction[b[i,k,1]]
```

- 한글 식: **첫 접안은 도착 예정시각에 빈 부두 접안 소요를 더한 시각 이후다**
- 예제 · A1: 접안 ≥ 도착 0.0 + 접안 소요 2.0 = 2.0h → 가장 이른 2.0h로 만들었다
- 예제 · B3: 가장 이르게는 6.0 + 2.0 = 8.0h. A1 뒤에 서도록 19.0h로 만들었다 (식 (18))

**(12) 하역 시작**

```text
a[i,k,m]  =  s[i,k,m]  +  δ_setup[i,k,m]
```

- 한글 식: **하역 시작 = 접안 + 하역 준비시간**
- 예제 · A1: 하역 시작 = 접안 2.0 + 준비 1.0 = 3.0h

**(13) 하역 완료**

```text
c[i,k,m]  =  a[i,k,m]  +  Q[i,k,m] / v[i, b[i,k,m]]
```

- 한글 식: **하역 완료 = 하역 시작 + (그 방문의 하역량 ÷ 그 부두의 하역속도)**
- 예제 · A1 · BUOY3: 하역 완료 = 하역 시작 3.0 + (12.0만 배럴 ÷ 시간당 1.0만 배럴) = 15.0h
- 예제 · A2 · BUOY2: 3.0 + (12.0 ÷ 0.8) = 18.0h

**(14) 호스분리**

```text
h[i,k,m]  =  c[i,k,m]  +  δ_hose[i,k,m]
```

- 한글 식: **호스분리 = 하역 완료 + 호스분리 소요**
- 예제 · A1: 호스분리 = 하역 완료 15.0 + 0.5 = 15.5h

**(15) 이안**

```text
u[i,k,m]  =  c[i,k,m]  +  δ_departure[i,k,m]
```

- 한글 식: **이안 = 하역 완료 + 이안 소요**
- 예제 · A1: 이안 = 하역 완료 15.0 + 2.0 = 17.0h

**(16) 유형 2 · 다음 부두 접안**

```text
s[i,k,m+1]  ≥  u[i,k,m]  +  τ_move[b[i,k,m], b[i,k,m+1]]        m = 1, …, M[i,k]−1
```

- 한글 식: **다음 부두 접안은 앞 부두 이안에 부두 간 이동시간을 더한 시각 이후다**
- 예제 · 설명용 A4: 다음 접안 ≥ BUOY3 이안 12.0 + 이동 3.0 = 15.0h

문장으로 정해 두는 것

- 이 시각들은 작업계획마다 미리 계산해 두는 숫자다. z와 따로 움직이는 변수가 아니다.
- 식 (11)과 (16)의 '≥'는 가장 이른 시각만 정한다. 그보다 늦은 접안 시각의 작업계획을 얼마나 더 만들지는 생성 설정(접안시각 생성 간격)이 정한다.
- δ_setup은 입력이 없으면 1시간, δ_departure는 2시간이다 (FR-29). δ_hose는 입력값이고, 없으면 과거 실적의 최빈값을 쓴다 (FR-30).
- τ_move는 앞 부두 이안부터 다음 부두 접안까지, δ_setup은 접안부터 하역 시작까지다. 두 시간은 겹치지 않는다.
- 방문은 다음을 모두 통과해야 작업계획에 넣는다: 부두 적합성(FR-14·15), 야간 도선(FR-19), 기상·공사 등 부두 사용 제한(FR-22), 계획기간(마지막 이안 ≤ 계획 종료).
- 하역을 중간에 멈추는 경우를 넣으려면 실제 작업 구간으로 완료 시각과 하역량을 다시 계산한다.

### 구간별 하역량

작업계획이 각 시간 구간에 탱크로 넣는 원유. 이동하거나 기다리는 동안은 0이다.

**(17) 구간별 하역량**

```text
q[i,k,t]  =  ∑[m=1..M[i,k]]  v[i, b[i,k,m]]  ×  | [τ[t], τ[t+1])  ∩  [a[i,k,m], c[i,k,m]) |
```

- 한글 식: **구간 t의 하역량 = 방문마다 (하역속도 × 그 구간과 하역 시간이 겹치는 길이)를 더한 값**
- 예제 · A1 · 구간 t=1 (3.0h~9.0h): 시간당 1.0만 배럴 × 겹친 6.0시간 = 6.0만 배럴
- 예제 · A1 · 구간 t=0 (0.0h~3.0h): 하역 시작(3.0h) 전이라 겹친 시간 0 → 0
- 예제 · B3 · 구간 t=8 (22.0h~28.0h): 1.0 × 6.0 = 6.0만 배럴

문장으로 정해 두는 것

- 재고 평가 시점 τ는 다음을 모아 시간순으로 놓은 것이다: 계획 시작 0, 계획 종료, 모든 작업계획의 하역 시작·완료 시각, 공정 소비속도가 바뀌는 시각. 작업중단을 넣으면 중단·재개 시각도 넣는다.
- 고르지 않을 작업계획의 시각까지 넣는다. τ는 풀기 전에 정해져 있어야 하기 때문이다.
- 이렇게 잡으면 구간 안에서는 재고가 직선으로만 변한다. 그래서 평가 시점만 검사해도 그 사이에서 범위를 벗어나는 일이 없다.
- D[t] = 구간 t의 공정 소비속도 × (τ[t+1] − τ[t]).

### 충돌 판정

서로 다른 입항 건의 두 작업계획을 방문끼리 모두 비교한다.

**(18) 같은 부두를 쓰는 두 방문**

```text
s[j,l,n]  ≥  u[i,k,m]  +  Switching[b]
또는
s[i,k,m]  ≥  u[j,l,n]  +  Switching[b]
```

- 한글 식: **뒤에 서는 쪽의 접안이 앞선 쪽의 이안에 교대시간을 더한 시각 이후여야 한다. 두 순서 가운데 하나만 되면 통과다**
- 예제 · A1 · B3 (BUOY3): B3 접안 19.0 ≥ A1 이안 17.0 + 교대 2.0 = 19.0 → 통과 (같은 시각)
- 예제 · A1 · B1 (BUOY3): B1 접안 8.0 < 19.0이고, A1 접안 2.0 < B1 이안 19.0 + 교대 2.0 = 21.0 → 두 순서 모두 안 됨 → F에 넣는다

문장으로 정해 두는 것

- 두 순서가 모두 안 되는 방문 쌍이 하나라도 있으면 그 작업계획 쌍 전체를 F에 넣는다.
- 같은 시각(=)은 통과다. 예: 접안 19.0 = 이안 17.0 + 교대 2.0.
- 예외: 뒤에 서는 쪽이 FIX 입항 건이면 같은 시각도 충돌로 본다. 멘토링 자료가 'FIX ETB ≤ 예상 ETU + Switching → 접안 불가'로 적었기 때문이다 (FR-17). **[덧붙임]**
- 동시 작업이 제한된 부두 조합의 두 방문은 s[j,l,n] ≥ u[i,k,m] − 2시간 또는 s[i,k,m] ≥ u[j,l,n] − 2시간 가운데 하나를 만족해야 한다. 아니면 F에 넣는다 (FR-20·21의 '접안 중인 선박 ETU − 2시간'). **[덧붙임]**
- 같은 입항 건의 두 작업계획은 식 (2)가 하나만 고르게 하므로 F에 넣지 않는다.

### 계약별 체선료

작업계획의 전체 일정에 계약 규칙을 적용해 금액 하나를 낸다.

**(19) 일반 꼴**

```text
C[i,k]  =  ContractCost( contract[i], schedule[i,k] )
```

- 한글 식: **체선료는 그 입항 건의 계약 규칙을 작업계획의 전체 일정에 적용한 값이다**
- 예제: A와 B 모두 식 (20) 꼴의 계약으로 두었다

**(20) 일일 정액 요율 + 시간 공제 계약**

```text
C[i,k]  =  (r[i] / 24)  ×  max( 0,  H[i,k] − ℓ[i,k] − A[i] − e[i,k] )
```

- 한글 식: **체선료 = (일 체선료 ÷ 24) × max(0, 사용시간 종료 − 정박개시 − 허용시간 − 공제시간)**
- 예제 · B3: (36,000 ÷ 24) × max(0, 호스분리 28.5 − 정박개시 8.0 − 허용시간 10.0 − 공제 0) = 1,500 × 10.5 = $15,750
- 예제 · A2: (48,000 ÷ 24) × max(0, 호스분리 18.5 − 정박개시 2.0 − 허용시간 14.0 − 공제 0) = 2,000 × 2.5 = $5,000
- 예제 · A1: 호스분리 15.5가 정박종료 16.0보다 이르다 → max(0, −0.5) = 0 → $0

문장으로 정해 두는 것

- H[i,k] = h[i,k,M[i,k]], 곧 마지막 방문의 호스분리다. 분할 하역이어도 허용시간 A[i]는 계약 전체에 한 번만 준다.
- ℓ[i,k]는 정박개시 규칙(FR-31·32)으로 계산한다. 규칙에 접안 시각이 들어가므로 작업계획마다 값이 달라질 수 있다.
- e[i,k]는 계약이 빼 주는 시간이다. 기상 공제(FR-35, 기상 악화로 인한 체선 시간의 절반)가 여기에 들어간다. 없으면 0이다.
- 식 (20)은 요구사항 FR-36과 같은 식이다: 체선 시간 = max(0, 호스분리 − 정박종료 − 기상 공제), 정박종료 = 정박개시 + 허용시간.
- 하역 중인 입항 건도 같은 식을 쓴다. 정박개시가 계획 시작보다 앞이어도 그대로 넣으므로 C[i,k]는 그 입항 건의 체선료 전액이다.

### 작업계획을 만들 때 정해야 하는 설정

- **접안시각 생성 간격** — 식 (11)은 '이후'만 정한다. 가장 이른 시각부터 몇 시간 간격으로 계획을 만들지.
- **최대 부두 방문 횟수 M_max[i]** — 유형 2에서 한 입항 건이 부두를 몇 번까지 방문할 수 있는지.
- **하역량 배분 간격** — 유형 2에서 방문별 하역량을 몇 배럴 단위로 나눠 볼지.
- **방문별 최소 하역량** — 식 (10)의 Q[i,k,m] > 0 대신 쓸 하한. 너무 작은 분할을 만들지 않게 한다.
- **계획 시작 · 종료일시** — 남은 물량을 모두 이 안에 처리해야 한다. 마지막 이안이 계획 종료를 넘는 계획은 만들지 않는다.

### 유형 2 계산 예 (설명용 A4, 검산 예제의 Ω에는 없음)

- BUOY3 7.0만 배럴: 접안 2.0 → 하역 3.0~10.0 → 호스분리 10.5 → 이안 12.0
- 이동 3.0시간(가상 값) → BUOY2 5.0만 배럴: 접안 15.0 → 하역 16.0~22.25 → 호스분리 22.75 → 이안 24.25
- 사용시간 종료 = 마지막 방문의 호스분리 22.75 → 초과 6.75시간 → 체선료 $13,500 (허용시간은 한 번만)

### 하역속도 v[i,b]를 '9.5 화물 이송율' 표에서 가져올 때

```text
v [배럴/시간]  =  이송율 [m³/시간]  ×  6.2898
```

- 표는 배관 공칭 직경과 유속(1 · 7 · 12 m/s)마다 시간당 이송량(m³/시간)을 준다. 예: 16″ 배관, 7 m/s → 2,968 m³/시간 × 6.2898 = 18,668 배럴/시간.
- 표의 값은 최대 허용 이송율이다. 실제 값은 사전 이송 회의에서 정한다고 적혀 있다. 그래서 식에 넣는 v는 표의 값 이하여야 한다.
- 식 (13)은 처음부터 끝까지 같은 속도로 계산한다. 초기 저속 구간이나 마무리 구간은 따로 나누지 않으므로 평균 속도를 넣는다.
- 표에서 값을 읽으려면 부두별 배관 직경, 적용할 유속, 동시에 쓰는 배관 수가 필요하다. 받은 자료에는 없다 → 판 9.
- 검산 예제의 1.0만 배럴/시간은 약 1,590 m³/시간이다. 표로 치면 12″ 배관을 7 m/s보다 조금 느리게 쓰는 정도의 가상 값이다.

- 정박개시 ℓ은 입항 건마다 주어진 값으로 두었다 (A 2h, B 8h). 실제로는 규칙(FR-31·32)으로 작업계획마다 계산한다.
