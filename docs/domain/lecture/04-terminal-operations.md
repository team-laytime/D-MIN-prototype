# M4 · 터미널 운영과 시간

- 핵심 질문: 부두에서 시간은 어디서 새고, 그 시간은 누구의 몫인가? 터미널은 무엇을 기록해야 자기 시간을 방어할 수 있나?
- 선수 자료: `../seagate-handoff.md` §1-3·§1-4, `../06-data-dictionary.md` §6
- 표기: [사실] / [추론] / [확인 필요] / [쟁점] / [가정]

## 학습 목표
1. 울산 CLX 입항 절차를 시간 순으로 그리고, 각 단계의 소요 시간이 어디서 정해지는지 말한다.
2. 접안 제약 네 가지(크기·시간대·조석·기상)가 대기를 만드는 방식과 그 대기의 귀책 가설을 설명한다.
3. 양하 속도를 결정하는 세 요소(선박 펌프·육상 배관·탱크 여유)를 구분하고 펌핑 분쟁의 증빙을 안다.
4. SOF를 표준 이벤트로 읽고 흔한 기록 오류를 잡아낸다.
5. 터미널이 남겨야 할 "방어 데이터" 목록을 만든다.

## 1. 입항에서 출항까지 — 울산 CLX 절차 타임라인 [사실, Entry Guide]

| 단계 | 내용 | 시간을 정하는 것 |
|---|---|---|
| 입항 보고 | 울산 PTMS(VHF Ch.14)에 입항예정 보고(항계 도착 1~2시간 전), 항계 진입·도착·이동·출항 보고 | 보고 누락 시 절차 지연 |
| 묘박 | 지정 묘박지(E-1~E-3 등) 투묘. 여기서 NOR | 선석 가용성 |
| 도선 | 접·이안·투묘·양묘 시 강제 도선(E-1~E-3 묘박지 제외). 항계 도착 2시간 전 울산파일럿(Ch.13/16) 호출. VLCC는 별도 승선 지점 | 도선사·예선 가용 시간대 |
| 이동·접안 | 묘박지 → 선석. 부두는 all fast, SBM은 finished mooring | 주간/야간 규칙, 조석, 기상 |
| 연결·점검 | 호스 연결, Ship/Shore Safety Checklist, 통신(하역 VHF Ch.71 등) | 준비 상태 |
| 하역 | 초기 유속 1 m/s 이하, 매니폴드 압력 7.5 kg/cm² 이하(방출 시), IG 산소 8% 이하 등 안전 수치 | 펌프·배압·탱크 |
| 분리·서류 | 호스 분리, 서류 완료 | 검정·서류 절차 |
| 이안·출항 | 이안은 24시간 가능(SK3~8), 출항 보고 | 도선·예선 |

> 수치는 SK Terminal Safety Regulation(인천판)과 Entry Guide에서 확인된 것이며 울산판은 같은 경로에 있을 가능성이 있다 [추론]. 풍속 한계 수치는 공개 자료에 없다 [확인 필요].

## 2. 접안 제약 네 가지와 대기의 귀책

| 제약 | 내용 [사실] | 대기가 생기는 방식 | 귀책 가설(Asbatankvoy) |
|---|---|---|---|
| 크기 | 선석별 최대 DWT·수심·길이(울산항만공사 표). 흘수 + 여유수심(UKC) ≤ 수심 | 큰 배는 선석 선택지가 하나(SBM) → 줄서기 | 혼잡 대기 = 용선주(reachable on arrival) |
| 시간대 | SK1~2 주간 접·이안(아스팔트·윤활유·유황 선적선 제외). SK3~8은 공선 30,000GT 이상·적재 25,000GT 이상 선박 접안 주간만, 이안 24시간. SBM 야간 계류 불가. 인천은 22:00~04:00 접안 제한 | 밤에 도착하면 아침까지 대기 | 판례 흐름은 용선주. cl.6 "통제 밖" 예외와 충돌 [쟁점]. 규칙 주체(항만당국 vs 터미널)가 영향 |
| 조석 | 인천은 대조기 조차 약 9.8 m, 조류 최대 약 3노트. 울산은 조차가 작아 영향이 덜한 것으로 보임 [추론] | 흘수 큰 배는 만조 시간창만 가능 | reachable on arrival 범위(판례) → 용선주 경향 |
| 기상 | 풍속·파고 한계 초과 시 접안·하역 중단. SBM이 특히 민감 | 접안 지연, 하역 중단 | 레이타임 중 산입. 체선 중 폭풍은 반액 |

"주간"의 정의(일출~일몰인지 고정 시각인지)는 공개 자료에 없다. 룰 `ULS-DAYTIME-DEF`는 07:00~17:30 [가정]이며, 현업 확인 후 KASI 일출몰 API로 교체하는 방안이 있다 [추천].

## 3. 양하 속도는 누가 정하나 — 세 요소

```
실제 양하 속도 = min( 선박 펌프 능력 , 육상 배관 허용(배압) , 탱크 수용 여유 )
```

| 요소 | 책임 | 느려지면 | 증빙 |
|---|---|---|---|
| 선박 펌프 | 선주 | 펌핑 워런티(24h 또는 100 psi) 미달 → 초과 시간 선주 부담 | 펌핑 로그(시간별 매니폴드 압력·유량) |
| 육상 배관·배압 | 터미널(용선주 측) | 선주는 LOP로 "육상 제한" 주장 → 공제 불가 | 터미널 배압 기록, 라인 구성, 밸브 조작 로그 |
| 탱크 수용 여유 | 터미널·생산(용선주 측) | 하역 중단·감속 → 용선주 시간 | 탱크 재고·수입 계획(SEAGATE 원유재고예측) |

원유 탱커는 **COW(crude oil washing)**와 스트리핑(잔량 배출)에 시간이 더 들고, 그 시간도 레이타임에 산입된다(선박 귀책이 아닌 한) [사실, 일반]. LPG는 예냉·증기 회수 등 절차가 달라 양하 시간 구조가 다르다 [추론].

**펌핑 분쟁의 핵심**: "100 psi를 유지했는데 터미널이 받지 못했다"(선주) vs "펌프가 약했다"(용선주). 판가름은 **매니폴드 압력 기록과 터미널의 배압·수용 기록을 같은 시간축에 놓는 것**이다. 이것이 Agent가 자동화할 수 있는 가장 명확한 대조 작업 중 하나다.

## 4. SOF 읽기

### 4-1. 표준 이벤트(`../06` §6)와 레이타임 역할
EOSP → PILOT_STATION_ARR → **ANCHORED**(도착선 판정) → **NOR_TENDERED / NOR_RECEIVED**(개시 계산) → FREE_PRATIQUE·CUSTOMS → PILOT_ON_BOARD → **ANCHOR_AWEIGH**(이동 시작) → FIRST_LINE → **ALL_FAST**(개시 대안·이동 종료) → GANGWAY → SSSCL_DONE → HOSES_CONNECTED → **OPS_COMMENCED** → OPS_STOPPED/RESUMED(사유 코드) → OPS_COMPLETED → **HOSES_DISCONNECTED**(종료) → DOCS_ON_BOARD → LAST_LINE → PILOT_AWAY → COSP

### 4-2. 흔한 기록 오류와 점검
| 오류 | 예 | 점검 |
|---|---|---|
| 시간대 혼동 | 선박은 UTC, 대리점은 KST | 모든 행에 tz 표기, 변환 로그 |
| 24:00 표기 | "D2 24:00" vs "D3 00:00" | 표준화 규칙 |
| 제출·수령 혼동 | NOR tendered 14:00, received 14:40 | 둘 다 기록, 개시는 received |
| 사유 누락 | "stopped" 만 있고 이유 없음 | 사유 코드 필수(WEATHER, SHORE_TANK, SHIP_EQUIPMENT, SHORE_EQUIPMENT, DOCUMENTS, SAFETY, OTHER) |
| 서명 누락 | 터미널 서명 없는 SOF | 3자 서명 확인, 없으면 증빙력 약화 |
| 묘박지 미기록 | 항계 진입 시각만 있음 | ANCHORED 시각으로 조기 NOR 판정 |

### 4-3. 예제 SOF(TC-02) 주석
`../04-worked-examples.md` 예제 2의 SOF를 §4-1 코드로 다시 쓰면: ANCHORED/NOR_RECEIVED D1 14:00 → (notice expiry D1 20:00) → ANCHOR_AWEIGH D2 06:30 → ALL_FAST D2 08:00 → HOSES_CONNECTED D2 09:00 → OPS_COMMENCED D2 09:30 → OPS_COMPLETED D3 05:30 → HOSES_DISCONNECTED D3 06:30. 이 8개 행이 계산서의 모든 줄을 만든다.

## 6. 터미널의 방어 데이터 — 무엇을 남겨야 하나 [추천]

| 데이터 | 왜 |
|---|---|
| 선석별 점유 시작·종료(all fast·last line) | 혼잡 대기 입증 |
| 접안 지시·불가 통보 시각과 사유(야간·기상·조석) | 대기 사유 분류, 반액 증빙 |
| 호스 연결·분리 시각(터미널 기록) | 레이타임 종료 시각의 권위 있는 기록 |
| 배압·유량·밸브 상태(시간별) | 펌핑 워런티 공제 방어 |
| 수용 탱크 상태·여유 | SHORE_TANK 사유 판정 |
| 하역 중단 지시 시각·사유 | 반액·귀책 |
| 기상 관측(풍속·파고, 터미널 측정 + KMA) | storm 입증 |
| 통신 로그(VHF·메일) | NOR 수령 시각, 통지 |
| LOP 발행·수령 | 분쟁 쟁점 사전 기록 |

터미널 기록이 곧 **클레임 방어 자산**이라는 점이 M5와 M6의 연결 고리다.

## 7. 터미널이 쥔 레버와 쥐지 못한 것

| 쥔 레버 | 효과 | 쥐지 못한 것 |
|---|---|---|
| 접안 순서·선석 배정 | 체선료 가중 대기 줄이기(요율 높은 배 먼저?) — 단 공정·탱크 제약 | 기상, 조석, 선박 도착 시각 |
| 사전 준비(탱크·라인·도선 예약) | 접안 후 지연 최소화 | 선박 펌프 능력 |
| 야간 규칙 예외(가능하다면) | 대기 단축 | 계약 조건(요율·허용 시간) |
| 하역 속도 조율(배압·수용) | 양하 시간 단축 | 선주 청구 자체 |
| 기록 품질 | 공제·반액 방어 | — |

SEAGATE에는 Berth Optimization·Berthing Simulation·부두제약관리가 이미 있다 [사실, 진단]. 우리 Agent는 그 결과에 **체선료 관점의 설명**(이 순서면 누가 얼마나)과 **기록 대조**를 더한다.

## 8. 자주 하는 오해
1. "밤에 못 붙이는 건 자연 규칙이니 아무도 책임 없다" → 계약상 대기 위험은 용선주에게 있다는 판례 흐름. 터미널 규칙이면 더욱 그렇다 [쟁점].
2. "펌프가 느린 건 선박 문제" → 배압·탱크 기록으로 "육상 제한 없음"을 입증해야 공제된다.
3. "SOF는 대리점이 알아서" → 터미널 서명이 없거나 사유가 비면 방어력이 떨어진다.
4. "기상 중단이면 시계가 멈춘다" → 탱커 레이타임은 멈추지 않는다. 체선 중 폭풍이면 반액.
5. "접안 순서는 선착순이 공정" → 체선료 노출은 요율·허용 잔여에 따라 배마다 다르다. 공정성과 비용 사이의 선택은 사람 몫.

## Agent에 주는 시사점
- 원인 코드(§5)가 OPS_STOPPED 사유와 대기 사유의 표준이 된다. 사람이 고르는 코드 대신 증거(앞 선박 종료 시각·기상 관측·탱크 상태)로 자동 분류 초안을 낸다.
- 터미널 방어 데이터(§6)의 필드가 `TERM` 출처 SOF_EVENT·EXTERNAL_OBS로 들어온다.

## 확인 문제
1. 양하 속도를 정하는 세 요소와 각 책임자는?
2. 선주가 "100 psi를 유지했다"고 주장할 때 터미널이 반박하려면 어떤 기록이 필요한가?
3. 야간 접안 제한으로 6시간 대기했다. Asbatankvoy에서 용선주가 들 수 있는 조항과 선주가 들 수 있는 조항은?

**정답** 1. 선박 펌프(선주), 육상 배관·배압(터미널), 탱크 수용 여유(터미널·생산). 2. 같은 시간축의 터미널 배압·유량·밸브 기록과 수용 탱크 상태(육상 제한이 없었음을 보여야 선주 펌프 미달로 공제 가능). 3. 용선주: cl.6 "용선주 통제 밖 사유의 접안 지연은 used laytime 불산입". 선주: cl.9 reachable on arrival(The Fjordaas 류). 결론은 쟁점이므로 플래그.
