M6 · 룰 엔진 · 쟁점 플래그 · Golden set

계산은 코드가, 설명은 LLM이, 결정은 사람이 한다

룰 엔진 원칙

  • 결정론: 시간 · 요율 계산은 코드
  • 룰마다 ID · 조항 · 확인 상태
  • 프로파일 계층: 기본 → 서식 → Rider → 매매계약
  • 시각 정규화, 버전 · 재현성
  • write는 초안만, 확정은 승인

쟁점 플래그 = 두 계산

  • SHIFT_ON_DEM 체선 중 이동
  • NIGHT_WAIT 야간 접안 대기
  • WX_HALF_SCOPE 레이타임 중 폭풍
  • NOR_EARLY 도착 전 NOR
  • LOAD_PORT_UNKNOWN 선적항 미확인

노란 배지 · 두 금액 병기 · 담당자 선택 · 감사 로그

Golden set

  • 1 TC = 계약 + SOF + 정답 + 플래그
  • 20건 손검증 → 50건 합성 → 현업 샘플
  • 정상 40 · 단일 쟁점 40 · 복합 20
  • 지표: 금액 ±1달러, 플래그 재현율, 근거 첨부율 100%
  • 룰 변경마다 회귀

LLM이 맡는 일: recap · SOF · 청구서 파싱, 쟁점과 차이의 설명, 회신 초안. 맡지 않는 일: 시간 합산, 쟁점 판정, 접안 · 클레임 확정.

체선료 도메인 집중 강의 · M6 · 34 · 06-data-and-agent.md §2~4

세 상자는 각각 M6 노트의 2, 3, 4절입니다. 가장 자주 받는 질문이 "LLM이 계산도 하면 안 되나"인데, 재현성과 근거가 무너지므로 안 된다고 답하세요. 쟁점은 판정하지 않고 두 계산을 내는 것이 완성이라는 점, Golden set을 룰보다 먼저 만든다는 점을 강조합니다.
