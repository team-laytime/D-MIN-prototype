## 3. 표기 규칙과 모듈 코드

- **[사실]** 공개 자료·표준서식 원문으로 확인 / **[추론]** 사실에서 도출, 현업 검증 필요 / **[추천]** 팀 제안 / **[가정]** 임의로 둔 수치·규칙 / **[확인 필요]** 원문·현업 확인 전 / **[쟁점]** 해석이 갈려 자동 판정하지 않을 것
- 모듈 코드: **INTAKE**(수집·파싱) · **CLOCK**(레이타임 시계) · **EXPOSURE·EXPLAIN**(노출 예측, 변경 1건의 영향 설명) · **SCHED**(SEAGATE 계획·최적화 결과를 체선료 관점에서 비교·설명. 새 솔버는 만들지 않음) · **CLAIM**(청구 대조·사유 분류·시효) · **COMMS·HITL**(초안·승인)
- 시각은 현지시각(KST) 기준 running hours. 금액은 USD, 요율은 USD/일을 24로 나눠 시간 비례.

## 4. 시뮬레이터 조작법

1. 상단 슬라이더나 재생 버튼으로 시각을 움직인다. 선석 간트와 레이타임 레인의 세로선이 "지금"이다.
2. 레이타임 레인에서 색을 읽는다: 회색 = 통지시간(미산입), 파랑 = 레이타임 산입, 빗금 = 이동(제외), 빨강 = 체선 전액, 주황 = 체선 반액.
3. 행을 누르면 그 선박의 **레이타임 계산서**(개시 규칙, 공제, 체선 시간, 금액, 룰 ID)와 **쟁점**(체선 중 이동, 야간 대기 부담 주체 등)이 열린다.
4. "접안 계획 편집"에서 선석을 바꾸거나 순서를 올리고 내리면 전체가 다시 계산된다. "D2 14:00–20:00 강풍 중단"을 켜면 하역 중단·접안 불가·반액이 적용된다.
5. "대안 순서 탐색"은 학습용 what-if다. SEAGATE에 이미 있는 Berth Optimization을 대체하려는 것이 아니라, 순서 변경 1건이 돈으로 어떻게 번역되는지 반복해서 보기 위한 것이다.

한계: 양하항 1개 항구의 허용 시간만 쓴 단순화, 운영 제약(공정·탱크·도선) 미반영, "주간" 07:00–17:30 가정.
