## 0. 한 장 요약

- **한 줄**: SEAGATE가 기록하는 체선 "시간"을 계약상 체선"료"로 바꾸고, 그 근거와 차이를 설명하고, 회신·통보 초안을 만들어 **담당자가 승인**하게 하는 Agent.
- **하는 일 세 가지**: ① 계산(결정론 엔진) ② 대조·설명(근거 인용) ③ 초안(승인 필수).
- **하지 않는 일**: 체선 대시보드, 선석 최적화 솔버, 자동 확정·발송, 쟁점의 자동 판정, 가상 수치를 실효과처럼 말하기.
- **코어 후보**: A 청구 검증(사후) 또는 B 노출 설명(사전). 멘토 질문 1번의 답으로 고른다 (D-01). 무응답이면 A를 기본값으로 제안한다 [추천].
- **지금 상태**: 계산 엔진·프로토타입·학습 자료·평가용 케이스는 있고, 현업 검증은 없다. 이 PRD는 "만든 것을 정당화"하지 않고 "무엇을 검증해야 하는지"를 고정하려는 문서다.

## 1. 문제와 SEAGATE 대비 위치 [가설]

**문제 문장 (멘토 확인 전)**: 체선 시간은 터미널이 재지만 체선료는 용선계약·매매계약이 정한다. 두 값을 잇는 일 — SOF·NOR 대조, 레이타임 계산, 공제·반액·시효 판단, 청구·통보 문서 작성 — 이 사람 손에 남아 있어서 느리고, 공제할 항목이나 청구 기한을 놓칠 수 있다 (진단 H4, [추론]).

**왜 지금 비싼가** [사실, [`../seagate-diagnosis.md`](../seagate-diagnosis.md) §4]: 2026년 중동 정세로 원유 도입선이 바뀌고 VLCC 용선료가 사상 최고 수준이어서 대기 1시간의 값이 커졌다.

| | SEAGATE에 이미 있는 것 (메뉴 이름 기준 [추론]) | 비어 있다고 보는 곳 = 우리 자리 | 근거 등급 |

## 4. 코어 선택(A/B)과 결정 규칙

| 항목 | A. 청구 검증 Agent (사후 루프) | B. 노출 설명 Agent (사전 루프) |
|---|---|---|
| 한 줄 | 청구서 1건 → 계약대로 재계산 → 차이·근거·회신 초안 | ETB 변경 1건 → 선박별 노출 변화·이유·대안·통보 초안 |
| 모듈 | INTAKE → CLOCK → CLAIM → COMMS·HITL | INTAKE → CLOCK → EXPOSURE·EXPLAIN → COMMS·HITL |
| 사용자 | 체선료 정산 담당 | 터미널 접안계획 담당 |
| 정답을 얻는 법 | 직접 만든다 (심은 오류) | 실제 접안계획·제약 데이터가 없으면 약하다 |
| 위험 | SEAGATE Demurrage가 금액·클레임까지 다루면 겹친다 | Berth Optimization과 경계가 흐려진다 |

**고르는 규칙** ([목표 정의서](https://claude.ai/artifact/EtGa6qgGegeoTAafPzzUgb) 그대로):

| 멘토 답 | 선택 |
|---|---|
| Q1: Demurrage·체선 리포트는 시간 지표뿐이고 정산은 Excel·메일로 따로 한다 | **A 코어**, B는 데모 확장 |
| Q1: SEAGATE가 금액·클레임까지 계산한다 | **B 코어**, A는 SEAGATE 금액과 대조하는 기능으로 축소 |
| Q3: Optimization 결과를 설명하기 어려워 잘 안 쓴다 | B에 무게 |
| Q2: 체선사유를 사람이 고르기만 하고 쓰임이 적다 | 어느 쪽이든 체선사유 분류(CLM-05)는 stretch |
| 실데이터를 받을 수 없다 | 정답을 직접 만들 수 있는 A가 유리 |

**기본값**: 기한(G1)까지 답이 없으면 **A**로 간다 [추천]. 이유: 정의서 규칙상 실데이터가 없을 때 A가 유리하고, 심은 오류로 정답을 직접 만들 수 있어 평가가 가능하다. 팀이 합의해야 확정된다 (D-01).

**공통**: INTAKE, CLOCK, COMMS·HITL은 두 분기가 함께 쓴다. 분기 요구의 우선순위는 그 분기가 코어로 확정될 때 유효하다. 선택되지 않은 분기의 Must는 Could로 내리고 "데모 확장"으로 부른다.
