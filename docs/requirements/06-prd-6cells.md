## 칸마다 보충

### 1. 누구의 어떤 문제인가?

- 근거 등급은 HYPOTHESIS다. 문제 문장은 03 §1(진단 H4 [추론]), 사용자는 03 §2의 "체선료 정산 담당 (A의 사용자)"이다.
- 모르는 것: 이 담당자가 SK에너지 소속인지 트레이딩 조직인지 [확인 필요: 질문지 Q1, Q10].
- 코어 A는 **임시 선택**이다. 멘토 답이 "SEAGATE가 금액·클레임까지 계산한다"이면 B로 바뀐다 (03 §4 고르는 규칙). 03의 D-01은 "대기"로 두고 "임시 선택 A"만 덧붙였다.

### 2. 우리가 만드는 것은?

- 03 §0의 한 줄("SEAGATE가 기록하는 체선 '시간'을 계약상 체선'료'로 바꾸고…")을 A 코어로 좁힌 문장이다.
- 흐름은 입력 → 재계산 → 차이·근거 → 회신 초안 → 사람 승인이다. 이 순서가 시연 시나리오 S-A1 ([`04-scenarios.md`](04-scenarios.md))이다.

### 3. 하지 않는 것은?

- 03 §3의 N-1~N-4와 같다. N-5(가상 데이터·가정값을 실제 효과처럼 발표하지 않기)도 03에 있다.
- 이유: ①②는 SEAGATE에 이미 있는 기능과 겹치고, ③④는 책임 문제다.

### 4. 잘 됐는지 어떻게 아나?

| 기준 | 지금 상태 | 메모 |
|---|---|---|
| ① 골든 케이스 7개 100% | 달성 (`clock/`) | EVL-01 |
| ② 줄마다 근거 | README 기준 달성 | 전수 점검 테스트는 [확인 필요] (CLK-03) |
| ③ 심은 오류 탐지 90%+ | 미착수 | 청구 30건을 만들어야 한다 (EVL-02). 90%는 정의서 예시값이라 팀이 확정해야 한다 |
| ④ 외부 발송 0건 | 구현됨 | COM-01. 10건은 [가정] |

일부러 넣지 않은 것: 절감액·ROI·채택률. 현업 데이터가 없어 지금은 주장하지 않는다 (03 §8 "도입 뒤에야 잴 수 있는 것").

### 5. 꼭 있어야 하는 기능

| 기능 | 요구 ID | 구분 | 현황 |
|---|---|---|---|
| 레이타임 재계산 | CLK-01~03 | 꼭 필요 | ✔ (근거 전수 점검은 확인 필요) |
| 청구와의 차이 분해 | CLM-01·02 | 꼭 필요 | △ ULSAN GLORY 이식 전, 사유 코드 체계 불일치 |
| 회신 초안 + 사람 승인 | CLM-03, COM-01 | 꼭 필요 | ✔ 템플릿 초안 + 웹 승인 |
| 도착 전 노출 설명 | EXP-01~04 | 확장 | ✔ 프로토타입에 있음, 정답 고정 세트 없음 |

**조정한 곳**: 넷 다 체크하셨지만 A를 코어로 정하셨으므로 4번은 '꼭'이 아니라 '확장'으로 적었다. 03 §4의 규칙("선택되지 않은 분기의 Must는 Could로 내리고 데모 확장이라 부른다")을 따랐다. 4번을 꼭 필요로 올리면 Must가 18개에서 21개로 늘고(EXP-01·02, EVL-03 추가) 정답 20건을 더 만들어야 한다. 기능 자체는 프로토타입에 이미 있어서 늘어나는 것은 주로 검증 일이다. 올리고 싶으면 이 칸과 03 §4를 같이 고친다.

| 마감일(중간·최종) | 간트 날짜 전부 (지금은 12/16 [가정]) | 교육 공지·담당자, D-04 |
| 평가 기준·과제 정의서 | 4번 성공 기준, 에이전트 구성(D-06) | 교육 공지·담당자, Q6 |

고르지 않으셔서 전부 "모름"으로 적었다. 이미 아는 것이 있으면 이 칸을 먼저 줄인다.
