# 처음 시작하는 법 — 이것부터 보세요

- 작성일: 2026-11-04 · 이 폴더의 문서가 많아 보이면 **이 파일 한 장만 읽고 시작**하세요. 나머지는 막힐 때 찾아보는 용도입니다.
- 표기: [가설] = 아직 현업 확인 전 / [확인 필요] = 아직 모르는 것. 모르는 것을 "모른다"고 적는 건 틀린 게 아니라 올바른 PRD의 시작입니다.

---

## 1. 두 가지만 기억하세요

| | 한 줄 | 비유 | 우리에게는 |
|---|---|---|---|
| 간트 차트 | 해야 할 일을 시간 순서대로 가로 막대로 늘어놓은 일정표 | 여행 일정표 | 마감까지 무엇을 언제 끝낼지, 뭐가 막히면 뭐가 밀리는지 본다 |
| PRD | 무엇을·왜·누구를 위해 만들고, 어떻게 되면 성공인지를 팀이 같은 말로 적은 글 | 집 짓기 전의 요구서(방 몇 개, 예산, 입주일). 설계도는 그다음이다 | 팀원과 멘토가 같은 그림을 보게 한다 |

PRD는 "그리는" 문서가 아니라 **"쓰는" 문서**입니다. 본문은 글과 표이고, 그림은 흐름도 한두 장이면 충분합니다.

## 2. PRD 직접 쓰기 — 6칸 채우기 (30분)

아래 6칸에 답하면 PRD의 뼈대가 됩니다. 가운데 열은 우리 프로젝트의 예시 답이니 고쳐 쓰세요. 오른쪽 "내 답"은 비워 두었습니다. 모르는 칸은 "모름"이라고 적습니다.

| # | 질문 | 우리 프로젝트의 예시 답 [가설] | 내 답 |
|---|---|---|---|
| 1 | 누구의 어떤 문제인가? | 체선료 정산 담당자는 선주 청구서를 SOF·계약서와 손으로 맞춰 보느라 오래 걸리고, 공제할 항목이나 청구 기한을 놓칠 수 있다 | |
| 2 | 우리가 만드는 것은? (한 문장) | SOF와 계약 조건을 넣으면 체선료를 다시 계산해 차이와 근거를 보여 주고, 회신 초안을 만들어 담당자가 승인하게 하는 에이전트 | |
| 3 | 하지 않는 것은? | 체선 대시보드, 선석 최적화 솔버, 자동 확정·발송 (SEAGATE에 이미 있거나 책임 문제가 생긴다) | |
| 4 | 잘 됐는지 어떻게 아나? | 정답이 있는 계산 케이스 7개를 100% 맞힌다. 계산서 줄마다 근거(룰 ID, SOF 행)가 붙는다 | |
| 5 | 꼭 있어야 하는 기능 3~5개는? | 레이타임 재계산 / 청구와의 차이 분해 / 회신 초안 / 사람이 승인해야만 확정 | |
| 6 | 아직 모르는 것은? | 청구 검증이냐 노출 설명이냐(멘토 질문 1번), 마감일, 평가 기준 | |

정민규가 2026-11-04에 채운 결과는 [`06-prd-6cells.md`](06-prd-6cells.md)입니다. 팀원은 위 표의 "내 답"에 먼저 각자 써 본 뒤 그 장과 비교하면 합의가 빨라집니다.

6칸이 채워지면 이 순서로 키웁니다.

1. 팀과 30분 읽고 고친다.
2. 5번 기능을 "요구사항 표"(ID, 한 문장, 통과 기준)로 푼다.
3. 시나리오(누가 어떤 순서로 쓰는가)를 붙인다.
4. 버전을 올린다 (v0 초안 → v1 합의).

이미 써 둔 PRD 초안은 [`03-prd-v0.md`](03-prd-v0.md)입니다. 처음부터 그걸 읽지 말고, **6칸을 먼저 직접 써 본 다음** 초안과 비교해 보세요. 그림이 필요하면 흐름도(예: [`04-scenarios.md`](04-scenarios.md) §1)를 draw.io나 Mermaid로 한두 장만 그립니다.

## 3. 간트 직접 그리기 — 5단계 (30분~1시간)

1. **마감일**을 적습니다. 모르면 "예상"이라고 적고 시작합니다.
2. 해야 할 일을 **순서 생각 없이 전부** 적습니다 (15~30개).
3. 각 일을 **결과물 이름**으로 바꾸고 걸리는 기간을 대충 적습니다. ("준비" ✗ → "멘토 질문지 발송" ○) 1주를 넘는 일은 쪼갭니다.
4. "이게 끝나야 저게 시작"인 것만 표시합니다. 이것을 **선행**이라고 부릅니다.
5. 결정하는 날(**이정표** ◆)과 **담당자**를 붙입니다.

처음에는 도구 없이 **표 하나**(구글 시트·엑셀)면 됩니다. 그림은 표가 완성된 뒤에 그립니다. 용어 하나만 더: 막히면 전체가 밀리는 길을 **핵심 경로**라고 합니다. 우리는 "멘토 질문지 → 인터뷰 → 코어 결정"이 그 길입니다.

## 4. 잘 만든 간트인지 확인하는 체크리스트

- [ ] 마감 선이 있다
- [ ] 오늘 선이 있다 (남은 시간이 보인다)
- [ ] 할 일 이름이 결과물이다 ("준비", "개발" 같은 막연한 말이 아니다)
- [ ] 막대 하나가 1주를 넘지 않는다 (넘으면 쪼갠다)
- [ ] "먼저 끝나야 할 일"이 표시돼 있다
- [ ] 결정하는 날(◆ 이정표)이 있다
- [ ] 한 줄에 담당이 한 명이고, 핵심 경로가 표시돼 있다

## 5. 오늘 할 일 3가지

1. **(15분)** §2의 6칸을 적어 본다.
2. **(10분)** 마감일, 중간 일정, 팀원 수, 평가 기준을 확인한다. 간트 날짜의 기준이 된다.
3. **(20분)** §3의 시작용 표에 우리 일을 옮겨 적는다.

그리고 **멘토 질문지 메일은 먼저 보내 두세요.** 답이 오는 데 시간이 걸려서, 늦게 보낼수록 전체 일정이 밀립니다.
