## 2. 계산식

```
개시   t0 = min(a + n, f)               a = NOR 제출, n = 통지시간 6h, f = 접안 완료(all fast)
                                        (f가 a보다 앞서면 t0 = a)
종료   t1 = h                           h = 호스 분리 = 마지막 선적·양하 완료 + 지연(기본 0)
사용   U  = (t1 − t0) − δ               δ = 레이타임 중의 양묘→접안 이동 시간
체선   D  = max(0, U − L)               L = 허용 레이타임
금액   C  = D × r / 24                  r = 하루 요율
```

같은 식을 한글 이름으로 쓰면 (기호 ↔ 한글: a NOR제출 · n 통지시간 · f 접안완료 · h 호스분리 · t0 레이타임개시 · t1 레이타임종료 · δ 이동공제 · U 사용시간 · L 허용시간 · D 체선시간 · r 요율 · C 체선료):

```
레이타임개시 = min( NOR제출 + 통지시간, 접안완료 )
레이타임종료 = 호스분리
사용시간 = ( 레이타임종료 − 레이타임개시 ) − 이동공제
체선시간 = max( 0, 사용시간 − 허용시간 )
체선료 = 체선시간 × 요율 / 24
```

- 공제 δ: 양묘 시점에 아직 레이타임이 남아 있으면(`양묘 − t0 < L`) 이동 시간을 뺀다. 이미 체선이면 뺀 시간 없이 산입한다 (once on demurrage, 엔진 기본).
- 룰 ID: ASB-06-NOR-START · ASB-07-SHIFTING-EXCL · LAW-ONCE-ON-DEM · ASB-11-END-HOSES · ASB-08-RATE-PRORATA
- 여유가 2시간 미만이면 `LOW-MARGIN` 경고 (J004: 체선 0, 여유 20분).

| 계산 입력 | CSV에서 읽는 곳 |
|---|---|
| a | `NOR 제출`의 일시 |
| f | `접안` 중 첫 선적·양하 시작 직전의 마지막 것 |
| h | 마지막 `선적 완료`·`양하 완료` (+ 지연, 호스 분리 기록이 CSV에 없음) |
| δ의 구간 | f 직전의 마지막 `양묘` → f |

## 3. CSV를 읽을 때 걸리는 것

- **일시가 비고 시각만 있는 행**(`13:45`, `00:45`)은 날짜를 추정한다. J001의 마지막 선적 완료가 `00:45`에만 있어서, 이걸 놓치면 종료가 2시간 45분 앞당겨진다. 기준은 "관련 시작 이벤트 뒤 처음 오는 같은 시각"이다 (추정은 J001 두 줄뿐).
- **시각이 전혀 없는 행**과, 이미 시각이 있는 이벤트의 **같은 HH:MM 중복**(J022)은 무시한다.
- **접안은 "첫 하역 직전의 마지막 접안"**이다. J006은 일반부두 07 접안(04-23)이 아니라 하역 선석 접안(04-25 21:05)을 쓰고, J020은 하역이 시작된 뒤에 찍힌 18:24 접안 기록을 쓰지 않는다.
- **가스부두를 거친 SUN VENUS 5항차**(J003·J005·J012·J019·J023)는 가스부두 구간 이벤트가 없다. SK #5-4 선적 구간만 계산하고, 수량도 그 구간 화물만 센다. `MULTI-CALL`
- **재접안 J022**: 양하 도중 이안해 묘박했다가 31시간 45분 뒤 다시 접안했다. 기본은 산입, 제외한 값을 대안으로 낸다. `RE-BERTH`
- 일시와 운항·하역 기록이 어긋나면 `일시`를 따른다. 접안 행은 두 기록이 모두 있는 13건 중 12건에서 운항기록이 하역기록보다 2~68분 이르다 (J013만 6분 늦음). 어느 쪽이 all fast인지는 [확인 필요]다. 운항기록을 all fast로 쓰면 이동 공제 구간이 달라져 J004(0 → 867 USD)·J016(+668)·J019(+36) 세 항차만 바뀌고, 합계는 +1,571 USD(0.13%)다.
- 부두 간 이동(J001·J006·J023 등)은 산입하고, 양묘→접안만 공제 대상이다 (cl.9, `clock/README.md` §11).

## 5. 수리계획법 모델 (`berth_milp.py`)

```
집합  i ∈ N 선박, k ∈ K 선석, a_ik 접근 가능(선박 i가 선석 k에 들어갈 수 있으면 1), B_i = {k : a_ik = 1} 가능 선석
상수  a_i NOR, σ_i 양묘→접안 시간, p_i 접안 완료→호스 분리, L_i 허용, r_i 요율, c_i = a_i + n
      g_out 호스 분리→선석 비움, g_in 선석 비움→다음 배 접안 완료, F_k 선석이 비는 시각
변수  s_i 접안 완료 시각, d_i 체선 시간, δ_i 이동 공제, x_ik 선석 배정, o_ij 순서(i가 j보다 먼저), z_i·y_i 공제 판정

min   Σ_i (r_i / 24) · d_i

(C0)  x_ik ≤ a_ik                    접근 불가(a_ik = 0)인 쌍은 변수 x_ik를 만들지 않는다(= 0)
(C1)  Σ_k x_ik = 1
(C2)  s_i ≥ a_i + σ_i
(C3)  s_i ≥ F_k + g_in − M(1 − x_ik)
(C4)  s_j ≥ s_i + p_i + g_out + g_in − M(1 − o_ij) − M(2 − x_ik − x_jk)        같은 선석에서 겹치지 않음
      s_i ≥ s_j + p_j + g_out + g_in − M·o_ij − M(2 − x_ik − x_jk)
(C5)  d_i ≥ s_i + p_i − c_i − L_i − δ_i ,   d_i ≥ max(0, p_i − L_i)
(C6)  δ_i ≤ σ_i z_i , δ_i ≤ σ_i y_i , δ_i ≤ s_i − c_i + M(1 − y_i)
      s_i ≥ c_i − M(1 − y_i) ,   s_i ≤ c_i + L_i + σ_i − ε + M(1 − z_i)
(C7)  주간 접안 선박: s_i = 24·day_i + w_i , 7 ≤ w_i ≤ 17.5 , day_i 정수      (선택)
```

### 한글 이름과 한글 식

변수마다 같은 한글 이름을 쓴다 (화면의 식 밑에 붙는 이름과 같다).

```
상수  a_ik 접근가능 · a_i NOR제출 · σ_i 이동시간 · p_i 작업시간(접안→호스분리) · L_i 허용시간 · r_i 요율 · n 통지시간 · c_i 통지만료(= a_i + n)
      g_out 이안시간 · g_in 접안준비 · F_k 선석비움 · M 큰수 · ε 미소값 · B_i 가능선석
변수  s_i 접안시각 · d_i 체선시간 · δ_i 이동공제 · x_ik 선석배정 · o_ij 앞뒤순서 · z_i 레이타임중 · y_i 만료후접안
      (C4에서만 앞 배·뒤 배를 가려 앞배접안·뒤배접안·앞배작업·앞배배정·뒤배배정이라 쓴다)
```

위 식을 한글로만 쓰면:

```
목적  총 체선료 최소화 = 선박별로 ( 요율 / 24 ) × 체선시간 을 더한 값
(C0)  선석배정 ≤ 접근가능
(C1)  선석별 선석배정을 더하면 1
(C2)  접안시각 ≥ NOR제출 + 이동시간
(C3)  접안시각 ≥ 선석비움 + 접안준비 − 큰수( 1 − 선석배정 )
(C4a) 뒤배접안 ≥ 앞배접안 + 앞배작업 + 이안시간 + 접안준비 − 큰수( 1 − 앞뒤순서 ) − 큰수( 2 − 앞배배정 − 뒤배배정 )
(C4b) 뒤배접안 ≥ 앞배접안 + 앞배작업 + 이안시간 + 접안준비 − 큰수·앞뒤순서 − 큰수( 2 − 뒤배배정 − 앞배배정 )
(C5a) 체선시간 ≥ 접안시각 + 작업시간 − 통지만료 − 허용시간 − 이동공제
(C5b) 체선시간 ≥ max( 0, 작업시간 − 허용시간 )
(C6a) 이동공제 ≤ 이동시간 · 레이타임중
(C6b) 이동공제 ≤ 이동시간 · 만료후접안
(C6c) 이동공제 ≤ 접안시각 − 통지만료 + 큰수( 1 − 만료후접안 )
(C6d) 접안시각 ≥ 통지만료 − 큰수( 1 − 만료후접안 )
(C6e) 접안시각 ≤ 통지만료 + 허용시간 + 이동시간 − 미소값 + 큰수( 1 − 레이타임중 )
```

C5a를 말로 읽으면: 호스 분리 시각(접안시각 + 작업시간)이 개시(통지만료)에 허용시간을 더한 시각을 넘은 만큼이 체선시간이고, 이동공제가 있으면 그만큼 뺀다.

### 선석(부두) 제약 — 무엇이 들어 있고 무엇이 없나

모델은 처음부터 **선석이 여러 개인 문제**로 세웠다(K, a_ik·B_i, x_ik, F_k). 아래 SC-01 예는 선석이 하나(SK7)인 특수한 경우일 뿐이고, 화면의 두 척 탭은 선석을 1개·2개로 바꿔 볼 수 있으며(접근 가능 표 포함) 8척 시나리오는 선석 3개다.

과제 원문(`official-brief.md`)이 후보가 지켜야 할 제약으로 드는 네 가지와 비교하면:

- **부두별 접안 가능 제품 → 들어 있음**: (C0) 접근 가능 a_ik. 처음에는 변수 정의역(B_i)에만 들어 있어 식으로 보이지 않았고, 지금은 C0 줄과 접근 가능 표로 드러냈다. 값은 **CSV에서 관측된 (화물군 → 하역 선석) 이력**으로 만든 가정이다(윤활기유 SK #3·#5-4, PX SK #3·#5-5). 선박 크기와 선석 제원이 CSV에 없어 물리적으로 맞는지는 확인하지 못했다. [확인 필요]
- **일출·일몰 → Python 모델에만 있음**: (C7) 주간 접안(07:00~17:30 [가정]). `solve_milp`·`brute_force`가 지원하고 테스트가 있지만 **화면에는 아직 없다.**
- **조석·기상 → 없음**: 시간창 데이터가 CSV에 없다. 과제 원문은 조석·일출·일몰·일기예보를 공공데이터포털에서 받으라고 한다.
- 그 밖에 없는 것: 선석 정비·폐쇄 시간창(F_k는 "비는 시각"만 있고 닫히는 시각이 없다), 선박·선석 제원(DWT·LOA·흘수·수심), 인접 선석이 배관·탱크·예선을 나눠 쓰는 제약, 선석마다 다른 작업시간(p_i는 선석과 무관한 값).

값을 지어서 넣으면 숫자가 그럴듯해 보여도 근거가 없어서 뺐다. 팀 프로토타입 시뮬레이터(`prototype/engine/sim.py`)에는 선박·선석 적합성(DWT·LOA·흘수+UKC), 주간 규칙, 풍속, 정비 시간창, 공유 자원 묶음이 이미 있어서, 이 MILP에 그 제약을 넣으려면 그쪽 입력(`prototype/data/live/`)을 가져와야 한다.

### 숫자를 넣으면 — SC-01 한 문제의 파라미터·변수·제약

```
파라미터        a   σ   p    L    r(USD/일)  r/24    c = a + n
  X             2   0   16   24   48,000     2,000   8
  Y             4   0   10   12   96,000     4,000   10
  공통          n = 6   g_out = 1   g_in = 1   F_SK7 = 6   (M = 102: 시간 범위에서 계산)

모델  변수 7개 = s_X, s_Y, d_X, d_Y, o_XY (+ x_X,SK7 = x_Y,SK7 = 1 고정)
  min   2000·d_X + 4000·d_Y
  (C3)  s_X ≥ 6 + 1 = 7 ,   s_Y ≥ 7                       선석이 7시에 비어야 접안
  (C4a) s_Y ≥ s_X + 16 + 1 + 1 = s_X + 18    (o_XY = 1)    X가 앞이면 Y는 18시간 뒤
  (C4b) s_X ≥ s_Y + 10 + 1 + 1 = s_Y + 12    (o_XY = 0)    Y가 앞이면 X는 12시간 뒤
  (C5a) d_X ≥ s_X + 16 − 8 − 24 = s_X − 16 ,   d_X ≥ 0
        d_Y ≥ s_Y + 10 − 10 − 12 = s_Y − 12 ,  d_Y ≥ 0

해  o_XY = 0 (Y 먼저)                          o_XY = 1 (X 먼저)
  s_Y = 7                (C3 등호)                s_X = 7                (C3 등호)
  s_X = 7 + 10 + 2 = 19  (C4b 등호)               s_Y = 7 + 16 + 2 = 25  (C4a 등호)
  d_Y = max(0, 7 − 12) = 0                        d_X = max(0, 7 − 16) = 0
  d_X = 19 − 16 = 3                               d_Y = 25 − 12 = 13
  목적 = 2000×3 + 4000×0 = 6,000  ← 최적          목적 = 2000×0 + 4000×13 = 52,000
```

이진변수 o_XY의 두 값을 각각 풀면 목적함수가 6,000과 52,000이고, 솔버는 작은 쪽을 고른다(분기한정법의 가지 두 개). 이 숫자들이 `docs/requirements/09-first-steps.md`의 SC-01 손계산 정답과 같다. 모델 전문은 `out/berth_model_sc01.lp`(23줄)와 `out/berth_model_stress_1h.lp`(175줄, 8척)이고 화면(§9)의 ④에도 있다. 실제 문제도 같은 방식으로 변수·제약마다 값이 있고, 화면의 ③에서 하나씩 볼 수 있다.

비선형인 식을 선형으로 푼 방법:

- `D = max(0, U − L)`: 비용이 d에 대해 늘어나는 방향이라 `d ≥ 식, d ≥ 0`만 걸면 최소화가 `max`를 만든다.
- `t0 = min(c, s)`: 접안이 빠르면(s < c) 사용 시간이 p, 늦으면 `s + p − c − δ`다. 둘 중 큰 값이 사용 시간이라 (C5)의 두 식으로 충분하다.
- 이동 공제(once on demurrage)는 조건부라서 이진변수 z(양묘 시점에 레이타임 중인가), y(접안이 c 이후인가)로 건다. 공제는 비용을 줄이는 쪽이라 상한 제약만 있으면 된다.
- 순서는 선석별 이진변수 o와 big-M(disjunctive)으로 건다.

하한: (C3)(C4)를 빼면 선박이 각자 혼자 있는 문제가 되고, 여기서 `d_i = max(0, p_i − L_i)`이다. §1의 "접안 지연이 만든 몫"이 이 하한과 실제의 차이다 (1,128,147 USD, 상한이지 예측이 아니다. 조석·주야·기상·선석 가용 때문에 전부를 없앨 수는 없다).

### 모델이 낸 값

## 9. 화면 — `explorer.html`

파일을 브라우저로 열면 된다. 위쪽 조건(허용 레이타임·요율·통지시간·호스 분리 지연, NOR 수령 기준, 투묘 전 NOR, 체선 중 이동, J022 중단 구간)을 바꾸면 모든 숫자가 같이 바뀌고, 조건은 주소의 `#...`에 남아 같은 화면을 다시 열 수 있다.

- **식 표기**: 모든 식은 **변수 밑에 한글 이름**을 달고(예: `s_i` 접안시각, `F_k` 선석비움), 바로 아래에 같은 식을 **한글 식**으로 한 줄 더 쓴다. 제약식에 숫자를 대입한 줄도 숫자마다 한글 이름이 붙는다(`접안시각 19 ≥ 선석비움 6 + 접안준비 1 …`). 기호식과 한글 식은 한 문자열(`sym{한글}`)에서 같이 만들어 어긋나지 않는다.
- **항차별 체선 탭**: 23항차 타임라인(체선은 빨강), 행을 누르면 그 항차의 **계산식 + 입력값(a, n, f, h, L, r) + 계산 단계(c, t₀, t₁, δ, U, D, C)**와 다른 해석으로 계산한 금액. 요약 막대에서 NOR 해석 세 가지의 총액을 눌러 바꾼다.
- **접안 순서 (수리계획법) 탭**: ① 모델의 식(집합·상수, 결정변수, 목적함수, 제약 C0~C6 — 선석 제약 C0·C1·C3·C4에는 "선석" 칩) ② 이 문제의 파라미터와 **접근 가능 a_ik 표**(두 척은 직접 입력하고 선석 SK8을 켤 수 있다, 8척은 실제 CSV 값) ③ 해에서 **모든 변수의 값과 모든 제약식에 숫자를 대입한 결과**(여유·등호 표시, 등호인 식이 접안 시각을 정한다) ④ 솔버에 넣는 LP 형식 모델 전문. 두 척은 값을 바꾸면 최적 순서가 바뀌는 것을 볼 수 있고, 8척은 같은 모델에서 MILP 해와 현업 Rule 해를 번갈아 넣어 비교한다.
